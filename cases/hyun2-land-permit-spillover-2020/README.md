# 토지거래허가구역 지정(2020.6.23) → 옆 동네 아파트 가격 (풍선효과)

> 학습·연구용 분석입니다. 정부·공공기관의 공식 평가가 아닙니다.

**질문**: 2020년 6월 23일 서울시는 잠실·삼성·대치·청담동을 토지거래허가구역으로 지정했다. 그 뒤 이 동네와 경계를 맞댄 옆 동네의 아파트 ㎡당 가격이 떨어진 동네보다 더 올랐나(풍선효과)? 지정한 동네 자체의 가격은 눌렸나?

토지거래허가구역 안에서는 일정 면적을 넘는 집을 살 때 구청의 허가를 받아야 하고, 산 사람이 2년 동안 직접 살아야 한다. 전세를 끼고 사는 갭투자가 막힌다. 그래서 수요가 바로 옆의 지정되지 않은 동네로 옮겨 가 그쪽 가격을 올렸다는 주장(풍선효과)과, 그렇지 않았다는 주장이 갈린다.

| 항목 | 내용 |
|---|---|
| 지정 동 | 강남 삼성·대치·청담, 송파 잠실 (발표 2020-06-17, 시행 2020-06-23) |
| 옆 동 | 지정 동과 법정동 경계를 맞댄 10곳: 강남 개포·논현·도곡·신사·압구정·역삼·일원, 송파 삼전·석촌·신천 |
| 그다음 동 | 옆 동과 경계를 맞댄 11곳 |
| 먼 동 (비교 기준) | 강남·서초·송파의 나머지 10곳 |
| 기간 | 2019-06 ~ 2021-03 월별. 2020-06은 발표와 시행이 겹쳐 뺀다. 2021-04-27 압구정·여의도 등 추가 지정 전에 끝낸다 |
| 결과 | 법정동·계약월별 ㎡당 거래가격 중위값(로그). 해제 신고된 거래는 뺀다 |
| 자료 | 국토교통부 아파트 매매 실거래가 API (공공데이터포털 15126469) |

## 이 폴더의 두 계획

| 파일 | 역할 |
|---|---|
| `analysis-plan.yaml` | **이 케이스의 주 분석 계획.** 아래 "용어 풀이"의 4개 집단 이중차분, 무작위화 추론, 민감도 분석, 계획 보완이 여기에 있다 |
| `plan.yaml` | `make flow`가 읽는 계획. 옆 동 10곳과 먼 동 10곳만 비교한다 |

**`make flow`** 는 이 저장소에서 케이스 하나를 명령 한 줄로 끝까지 돌리는 도구다(`make flow CASE=cases/<폴더>`). 여섯 단계를 차례로 실행한다.

1. `plan.yaml`이 형식에 맞고 git에 커밋되어 있는지 확인한다. 커밋 전이면 멈춘다.
2. `fetch.py`로 자료를 받아 `data/panel.csv`를 만든다.
3. 열 이름·결측·중복을 점검한다.
4. `plan.yaml`에 적은 방법으로 효과를 추정하고, 미리 정한 조건에 걸리면 판정을 낮춘다.
5. 근거가 부족하면 "입증", "때문에" 같은 표현을 막는다.
6. `report.md`를 만든다.

`make flow`는 "정책을 받은 집단 하나 vs 받지 않은 집단" 비교만 할 수 있다. 이 케이스는 정책과의 거리에 따라 집단을 넷으로 나누므로, 전체 분석은 `analysis-plan.yaml`대로 따로 하고 `make flow`에는 그중 풍선효과 비교 하나만 맡긴다. 결론은 `analysis-plan.yaml`의 규칙으로 내리고, `make flow` 결과는 옆에 함께 싣는다.

## 용어 풀이

- **4개 집단**: 지정 동(4곳), 옆 동(10곳), 그다음 동(11곳), 먼 동(10곳). 풍선효과가 있다면 지정 동에 가까울수록 크게 나타나야 하므로 거리별로 나눴다.
- **이중차분(difference-in-differences)**: "지정 전후로 옆 동 가격이 얼마나 변했나"에서 "같은 기간 먼 동 가격이 얼마나 변했나"를 뺀다. 예를 들어 옆 동이 8%, 먼 동이 5% 올랐다면 차이 3%p를 정책과 관련된 변화로 본다. 서울 전체에 같이 작용한 금리·대출 규제 같은 영향이 빠진다.
- **4개 집단을 한 모형에 넣은 이중차분**: 지정 동·옆 동·그다음 동을 각각 먼 동과 비교하는 세 차이를 한 회귀식에서 함께 추정한다. 세 값은 직접 효과(지정 동 − 먼 동), 풍선효과(옆 동 − 먼 동), 거리 차이(옆 동 − 그다음 동)다.
- **무작위화 추론(randomization inference)**: 35개 동의 집단 이름표를 무작위로 5,000번 섞어 같은 계산을 반복한다. 그러면 "아무 효과가 없을 때 우연히 나올 수 있는 차이"의 분포가 생긴다. 실제 차이가 그 분포의 바깥쪽 5%에 있으면 우연으로 보기 어렵다고 판단한다. 지정 동이 4곳뿐이라 보통의 표준오차 계산이 믿기 어렵기 때문에 이 방법을 주로 쓴다.
- **민감도 분석**: 설정을 조금 바꿔도 결론이 유지되는지 본다.
  - S1: 1990년 이전에 지은 단지의 거래를 뺀다.
  - S2: 비교 기준을 서울 전체의 먼 동(304곳)으로 넓힌다.
  - S3: 거래가 드문 율현동을 뺀다.
- **계획 보완**: 계획을 처음 고정한 뒤, 지정 이후 가격을 보기 전에 덧붙인 내용이다(`analysis-plan.yaml`의 `amendments`). 지정 전 기간 점검과 외부 검토에서 나온 문제를 반영했다. 비교 집단·기간·결과 지표·주 모형은 그대로 두고 아래 세 가지를 더했다.
  - **결론 규칙:** 95% 신뢰구간을 쓰고, 세 차이를 함께 검정한 만큼 p값을 보정한다(Holm 보정).
  - **보조 분석:**
    - 고가주택 대출 규제 노출 보정: 2019-12-16 대책에 동네마다 다르게 노출된 정도를 빼고 본다.
    - 같은 단지 안에서 비교: 거래된 아파트의 구성이 바뀐 영향을 뺀다.
    - 거래 수 점검
    - 과거 해의 가짜 지정일: 정책이 없던 해에도 이만한 차이가 나는지 본다.
    - 동네별 추세 보정
    - 평행추세가 깨진 정도에 따른 결과 범위
  - **한계 표기:** 같은 시기 다른 정책을 한계로 적는다.
- **MDE(최소 검출 효과)**: 이 설계가 80% 확률로 잡아낼 수 있는 가장 작은 효과다. 옆 동 비교의 MDE는 0.076(약 8%)이다. 실제 효과가 이보다 작으면 놓칠 수 있다.
- **평행추세**: 정책이 없었다면 두 집단의 가격이 같은 흐름으로 움직였을 것이라는 가정이다. 이중차분은 이 가정에 기대므로, 지정 전에 흐름이 같았는지 먼저 점검한다.

## 무엇을 언제 봤나

결과를 보고 계획을 고치지 않았다는 것을 보이기 위해 순서를 남긴다.

1. 2026-10-18 `analysis-plan.yaml`을 고정했다. 이때 가격은 하나도 계산하지 않았다.
2. 서울 25개 구 × 2019-06~2021-03 거래를 받았다. 그 뒤 **지정 전 기간(2019-06~2020-05)의 결과만** 계산했다.
3. 독립 검토 네 건을 받아 계획 보완을 더했다.
4. 이 폴더의 `plan.yaml`을 썼다. 지정 전 결과를 본 뒤에 추가한 계획이다.

5. 2026-10-19 지정 이후(2020-07~2021-03) 가격을 처음 읽어 지정 전후 비교를 계산했다. 계획과 지정 전 단계 코드는 고치지 않았다. 지정 전 결과(`results/pre-period.json`)를 먼저 커밋하고 지정 전후 비교(`results/post-period.json`)를 뒤에 커밋했다.

지금까지 본 숫자는 `analysis-plan.yaml`의 `disclosures`에 모두 적었다. 결과와 해석은 `discussion.md`에 있다.

## 이미 본 지정 전 결과와 그 뜻

지정 전 기간 안에서 2019-12를 가짜 지정일로 두고 같은 비교를 해 봤다. 정책이 없던 때이므로 차이가 0 근처여야 정상이다. 단위는 log point다(−0.10 ≈ −10%). 괄호 안은 무작위화 추론 p값이다.

| 방법 | 지정 동 − 먼 동 | 옆 동 − 먼 동 |
|---|---|---|
| 동별 중위값 (주 분석 방식) | −0.124 (0.054) | −0.125 (0.009) |
| 15억 원 초과 거래 비율 보정 | −0.076 (0.22) | −0.098 (0.036) |
| 같은 단지 안에서 비교 | −0.040 (0.040) | −0.033 (0.024) |
| 과거 해(2015~2019) 같은 달의 가짜 지정일 | −0.029 ~ +0.033 | −0.077 ~ +0.049 |

- 2019-12 이후 지정 동과 옆 동은 먼 동보다 약 12% 덜 올랐다. 정책이 없던 시기인데도 차이가 났다는 뜻이다. 같은 달 2019-12-16 대책이 15억 원 넘는 아파트의 담보대출을 막았다. 지정 전 15억 원 초과 거래 비율은 지정 동 81%, 옆 동 64%, 먼 동 13%였다. 그래서 이 대책이 원인일 수 있다(추정이며 확인하지 않았다).
- 같은 단지 안에서 비교하면 차이가 3분의 1 정도로 준다. 차이의 상당 부분은 어떤 아파트가 거래됐는지가 바뀐 데서 온 것으로 보인다.
- 계획은 p값이 0.10보다 작으면 그 비교에 «원래 흐름 차이 의심» 표지를 붙이게 했다. 직접 효과와 풍선효과 모두 이 표지가 붙었다. 효과 추정치는 그대로 보고하되, 이 표지를 옆에 단다.
- `make flow`도 비슷한 규칙을 쓴다. 지정 전 흐름 검정의 p가 0.10보다 작으면 판정을 `not_identified`(식별 불가)로 낮춘다. 정책 전부터 흐름이 달랐으니 지정 뒤의 차이를 정책 효과로 볼 수 없다는 뜻이다. 지정 전 결과를 봤을 때는 `make flow` 판정도 식별 불가가 될 가능성이 크다고 봤다. 실제로는 지정 전 흐름 검정(범위 [-4, 8])은 통과하고(p 0.36) 가짜 지정일 검정이 걸려(p 0.005) 판정이 «조건부»로 나왔다.

## 결과를 어떻게 보고하나

`make flow`가 만드는 `report.md`의 맨 위 판정은 `plan.yaml`의 비교 하나(옆 동 vs 먼 동)에 대한 것이다. 주 분석 결과는 `estimate.py`가 따로 계산한다. 그 결과 표와 해석은 `discussion.md`에 적고, `report.md` 끝에 붙는다.

주 분석도 "정책 전부터 흐름이 달랐다"는 한계를 없애지는 못한다. 그 대신 "식별 불가" 한 단어보다 더 구체적인 말을 할 수 있다.

- **흐름 차이가 보이지 않은 비교:** 옆 동 − 그다음 동(거리에 따른 차이)은 지정 전 검정의 p가 0.60, 가짜 지정일 검정의 p가 0.74였다. 지정 전에는 두 집단이 비슷하게 움직였다는 뜻이다. 풍선효과가 있다면 지정 동에 가까운 옆 동이 더 올라야 하므로, 이 비교가 가장 믿을 만한 증거가 된다.
- **원인 후보를 뺀 비교:** 같은 단지 안에서 비교하거나 고가주택 대출 규제 노출을 빼면 지정 전 차이가 줄어든다. 지정 뒤 차이가 이렇게 남은 지정 전 차이보다 훨씬 크면 의미가 있다.
- **평소 출렁임과 비교:** 정책이 없던 2015~2019년에도 옆 동 − 먼 동 차이는 −8%~+5% 범위에서 움직였다. 실제 추정치가 이 범위 밖인지 본다.
- **결론이 뒤집히는 조건:** "지정 뒤 흐름 차이가 지정 전 월별 변화의 몇 배까지 커지면 결론이 뒤집히는가"를 숫자로 낸다.

차이가 MDE(약 8%)보다 작으면 이 설계로도 "판별 불가"가 될 수 있다고 미리 적어 두었다. 실제 결과는 `discussion.md`에 있다.

## 데이터와 이용 조건

- 공공데이터포털 표기는 «이용허락범위 제한 없음»이다(공공누리 유형 표기 없음, 2026-10-18 확인). 스키마에 맞는 값이 없어 `license: other`로 적었다.
- 원자료, `data/deals.csv.gz`, `data/panel.csv`는 커밋하지 않는다. `fetch.py`로 각자 받는다(`DATA_GO_KR_API_KEY` 필요).
- 2020-02-21 해제 신고가 의무가 되었다. 그래서 해제 표시 비율이 시기와 집단마다 다르다. 직거래 여부를 나타내는 값은 이 기간에 비어 있다.

## 다시 만들기

```bash
python cases/hyun2-land-permit-spillover-2020/fetch.py           # 약 740쪽 요청, 3분 안팎. data/ 에 저장
python cases/hyun2-land-permit-spillover-2020/estimate.py pre    # 지정 전 단계 → results/pre-period.json (약 8분)
python cases/hyun2-land-permit-spillover-2020/estimate.py post   # 지정 전후 비교 → results/post-period.json (약 1분)
make flow CASE=cases/hyun2-land-permit-spillover-2020            # plan.yaml 비교 → flow_log.json, report.md, figures/
```

- `make flow`는 `fetch.py`만 실행하고 `estimate.py`는 실행하지 않는다. 주 분석 숫자는 `estimate.py`로 따로 만든다.
- `estimate.py post`는 `results/pre-period.json`이 같은 입력(`analysis-plan.yaml`, `fetch.py`, `estimate.py`, `data/deals.csv.gz`의 sha256)으로 계산됐을 때만 돈다.
- 무작위화 추론의 난수 seed가 고정되어 있어 같은 자료면 같은 숫자가 나온다. 2026-10-19에 받은 자료는 742쪽, 243,093행이었다(`fetch.py`가 `deals.csv.gz`의 sha256을 출력한다). 포털이 나중에 신고를 고치면 숫자가 조금 달라질 수 있다.
