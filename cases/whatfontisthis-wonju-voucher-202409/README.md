# 원주사랑상품권 할인 상향과 결제 변화 (2024년 9월)

**작성자: whatfontisthis · 트랙 B 가설과 분석 · 2026년 10월 25일 개정(v2)**

우리가 알아보려는 것은 **“상품권을 더 싸게 살 수 있게 해주면, 그 상품권으로 결제하는 돈이 늘어날까?”**예요. 사례는 2024년 9월 원주시예요. 당시 모바일 원주사랑상품권의 구매 할인이 7%에서 10%로 올라갔어요. 10만 원짜리 상품권을 살 때 내는 돈이 9만 3천 원에서 9만 원으로 줄어드는 셈이에요.

| 일별·주별 자료가 있나요? | **없어요.** 결제정보는 월 단위 합계만 줘요. 그래서 처음 계획(주 단위)을 월 단위로 바꿨어요. |
| 결과는요? | 원주의 9월 모바일 결제금액은 비교한 7곳과 거의 같이 움직였어요. 차이 추정은 -2%이고 오차 범위가 -14%~+17%라서 **늘었는지 줄었는지 알 수 없어요.** |
| 할인이 효과가 없었다는 뜻인가요? | 아니에요. “효과를 찾지 못했고, 이 자료로는 찾기 어렵다”는 뜻이에요. 이유는 아래 5장에 있어요. |

## 1 무엇이 언제 바뀌었나요

- 공식 근거는 **원주시공고 제2024-2250**이에요. 시행일은 **2024년 9월 2일 오전 10시**예요. [원주시 공식 공고](https://www.wonju.go.kr/www/selectBbsNttView.do?bbsNo=140&key=216&nttNo=444171)
- 대상은 모바일 원주사랑상품권의 구매 할인이고, 7%에서 10%로 3%포인트 올랐어요. 2024년 9월 동행축제와 추석을 위한 한시 혜택이에요.
- **판매정책정보 API로도 확인했어요.** 원주는 9월 3일부터 10%(월 구매한도 30만 원), 10월 3일부터 다시 7%로 기록돼 있어요(9월 1~2일은 기록이 비어 있어요). 공고와 API가 같은 이야기를 해요.
- 원주의 2024년 1~5월 할인율은 6%, 8%, 10%, 8%로 달마다 바뀌었어요. 그래서 **정책이 안정적이었던 변경 전은 6~8월 석 달뿐**이에요.

## 2 처음 계획에서 무엇이 바뀌었나요

| | 처음(10월 18일) | 지금(10월 25일) |
| --- | --- | --- |
| 단위 | 주(월~일), 변경 전 11주 · 후 4주 | **월**, 변경 전 3개월(6~8월) · 후 1개월(9월) |
| 비교 대상 | 비슷한 규모의 일반시 5곳 이상(미정) | **정책과 자료 품질 규칙을 통과한 조폐공사 운영 시군 7곳** |
| 바뀐 이유 | | 결제정보 API에 일·주 조회가 없고 월 합계(`crtr_ym`)만 있어요. 처음 계획에는 “월별 자료만 있으면 주간 분석을 실행하지 않는다”고 적어 두었어요. 그 조건에 걸려서 설계를 바꿨어요. |

처음 계획은 커밋 `7e8c6b8`에 그대로 남아 있어요. **중요:** 이번 개정은 월별 합계를 한 번 훑어본 뒤에 썼어요. 분석 계획은 자료를 보기 전에 확정해야 한다는 원칙에서 벗어난 점이에요. 비교 도시를 결과 값이 아니라 정책·자료 품질 규칙으로만 골랐고(3장), 규칙을 코드(`fetch.py`)로 고정해서 이 문제를 줄였어요. 그래도 완전히 없어지지는 않아요.

## 3 어떤 도시와 비교했나요

공공데이터 판매정책정보는 **한국조폐공사가 운영하는 81개 지역**만 담고 있어요. (코나아이, 농협 등 다른 운영대행사 지역은 정책 자료가 없어서 비교할 수 없었어요. 춘천·강릉·충주 같은 처음 후보가 빠진 이유예요.) 이 81곳에 아래 세 규칙을 그대로 적용했어요. 결과 값은 보지 않아요.

| 규칙 | 내용 | 탈락 |
| --- | --- | ---: |
| R1 정책이 그대로 | 2024년 6월 1일~9월 30일에 할인율·월 구매한도가 한 가지뿐 | 52곳 |
| R2 자료가 충분 | 2024년 1~10월 모든 달에 모바일 결제금액이 있고 매달 1억 원 이상 | 20곳 |
| R3 급변 없음 | 인접한 달 사이 로그 변화가 0.5 이하 | 1곳 |
| **통과** | 시흥시, 보령시, 서천군, 태안군, 문경시, 합천군, 남원시 | **7곳** |

눈에 띄는 사실이 하나 있어요. **R1에서 탈락한 52곳 중 40곳이 2024년 9월에 6~8월에는 없던 할인율이나 구매한도를 도입했어요.** (나머지는 6~8월 안에서 바뀐 8곳, 정책 기록이 없는 4곳이에요.) 추석과 동행축제 때문에 한시 혜택이 전국에서 겹친 거예요. 그래서 “9월에 아무 혜택도 안 바꾼 곳”은 7곳뿐이에요. 탈락 지역과 이유는 `data/selection.csv`에 남아요.

**한계:** 7곳은 원주와 규모가 달라요. 시흥은 원주보다 훨씬 크고(월 모바일 결제 약 196억 원), 문경은 훨씬 작아요(약 4.6억 원). 금액에 로그를 씌워서 규모 차이를 줄였지만, 같은 방향으로 움직일 이유가 충분하다는 뜻은 아니에요. 인구 규모(원주의 0.5~2배)는 맞추지 못했어요. 인구 원표를 확보하지 못했고, 규칙을 통과한 곳 자체가 적기 때문이에요.

## 4 무엇을 비교했나요

한 행은 **시군 하나의 한 달 기록**이에요(8곳 × 4개월 = 32행). 주 지표는 `log(1 + 월간 모바일 결제금액)`이고, 보조 지표는 모바일 이용자 수(칸 합)예요. 원주의 6~8월 대비 9월 변화에서 비교 7곳의 같은 변화를 빼요. 이 방법이 **이중차분**이에요. 도시마다 원래 다른 점과 모든 도시에 공통인 달별 변화를 함께 고려해요.

## 5 결과와 해석

> 아래 숫자는 공용 분석 흐름(`make flow`)과 `extra_checks.py`가 계산한 실제 자료의 결과예요.

| 점검 | 결과 |
| --- | --- |
| 기본 비교 (원주 vs 7곳, 9월) | **-0.022** (약 -2%), 95% 신뢰구간 -0.155 ~ +0.156, 판정 **조건부** |
| 이용자 수로 바꿔서 | +0.019 (약 +2%), 신뢰구간 -0.024 ~ +0.077 |
| 비교 지역을 하나씩 빼기 | -0.031 ~ +0.001. 어느 지역을 빼도 0 근처예요 |
| 시(市) 4곳만 비교 | +0.013 (약 +1%) |
| 10월(7%로 복귀) | +0.001 (약 0%) |
| 가짜 시점(8월, 7월을 사후로) | -0.024, -0.015. 실제 추정(-0.022)과 크기가 비슷해요 |
| 도시를 바꿔치기한 8곳 중 | 원주 자신을 포함해 원주만큼 큰 값이 6곳 (p = 0.75) |

**읽는 법:** 원주의 9월 변화는 비교 지역들의 평소 흔들림 안에 있어요. 처치가 없던 달에도 같은 크기의 “차이”가 나와요. 그래서 이 자료로는 할인 상향이 결제를 늘렸다고도, 안 늘렸다고도 말할 수 없어요.

**왜 못 찾았을 수 있나요?**
1. **한 달 자료예요.** 할인은 3% 포인트 차이인데, 월 합계에서는 추석과 계절 변화에 묻힐 수 있어요.
2. **구매와 사용 시점이 달라요.** 할인은 상품권을 살 때 적용되고, 결제금액은 쓸 때 잡혀요. 9월에 싸게 산 상품권을 10월에 쓰면 9월 결제에 안 보여요.
3. **원주는 이미 높은 혜택에 익숙했어요.** 6%~10% 사이를 오가던 곳이라 7%에서 10%로의 변화가 작게 느껴졌을 수 있어요.
4. **비교 지역이 7곳뿐이고 규모가 달라요.**

## 6 말할 수 있는 것과 없는 것

- 말할 수 있어요: 월 단위 자료에서 원주의 9월 모바일 결제금액은 정책이 그대로였던 7개 시군과 비슷하게 움직였고, 효과의 크기와 방향은 판별할 수 없었어요.
- 말할 수 없어요: 할인 상향이 효과가 없었다는 것, 소상공인 전체 매출이나 새로 늘어난 소비에 영향이 없었다는 것.
- 더 좋은 답을 얻으려면: **일별 결제자료**가 필요해요. 원주시나 한국조폐공사에 요청해 볼 수 있어요. 그러면 원래 설계(시행일 오전 10시 기준 일·주 비교)로 돌아갈 수 있어요.

## 자료 출처와 주의

- [조폐공사 지역사랑상품권 결제정보](https://www.data.go.kr/data/15108292/openapi.do), [판매정책정보](https://www.data.go.kr/data/15125217/openapi.do): 이용허락범위 ‘제한 없음’. 특정 공공누리 유형으로 추정하지 않아 `license: other`로 적었어요.
- `region_codes_komsco.csv`는 결제정보 안내 페이지의 참고문서(사용처지역코드.xlsx)에서 조폐공사 운영 82개 지역의 코드와 이름만 옮긴 표예요.
- 정책 자료는 카드와 모바일이 합쳐진 기록이에요(`cardMobile`). 모바일만의 할인율은 아니에요. 원주는 모바일 상품권 할인이 공고로 따로 확인돼요.
- 모바일 금액 기준이 승인일인지 정산일인지, 환불이 어떻게 반영되는지는 문서에 없어요.
- 이용자 수(`mbl_user_cnt`)는 성별·연령·읍면동 칸의 합이라 사람 수가 아니에요.
- 원자료·인증키·분석용 표는 커밋하지 않아요.

## 기술 참고

- 계획 형식 검사와 `make flow` 실행이 통과해요. 공용 코드는 처치 단위가 1개라서 클러스터 표준오차 대신 무작위화 추론을 자동으로 써요. 클러스터가 8개로 `min_clusters: 20`보다 적어서 “조건부” 판정이 붙어요. 경고를 없애려고 기준을 낮추지 않았어요.
- 공용 `did` 경로는 사전추세 검정과 한 곳씩 빼기를 자동으로 하지 않아요. 한 곳씩 빼기와 바꿔치기는 `extra_checks.py`로 직접 계산했어요. 사전 기간이 3개월뿐이라 사전추세 검정은 하지 않았어요.
