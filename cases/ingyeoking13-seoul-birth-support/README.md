# 서울 자치구 출산지원금 변경과 출생등록 비교

공식 정책 근거를 대조하고, **서울 25개 구의 2018~2024년 월별 출생등록 2,100행을 수집해 분석했다.**
정책 이력 검증 기준을 충족한 증액 2개 구(중구·강남구), 유지 3개 구(용산구·성동구·송파구)를 비교한다.
나머지 20개 구는 적용일 차이 2개, 전체 이력 검증 부족 18개로 제외했다.
25개 구 전체의 정책 이력을 모두 검증하거나 서울 전체 효과를 추정한 것은 아니다.

**결론은 인과효과 판단 불가다.** 비교값은 양수지만 처치 구 2개·전체 5개라는 작은 표본,
산후조리·다자녀 지원 등의 동시 변화, 신고기준 지표의 한계가 있다.
공통 엔진의 p=0.001·좁은 구간을 인과적 유의성으로 해석하지 않는다.
서로 다른 가짜 배정 3개를 999회 반복하는 구현의 한계와 별도 전수 배정 진단을 기록했다.

- [분석 리포트](report.md): 사전 계획의 추정·그림·보류 판정·해석 한계.
- [25개 구 기술통계](descriptive-report.md): 모든 구의 추세와 2022~2024년 변화, 작은 표본의 추론 진단.
- [정책 검증 기록](policy-review.md): 구별 포함·제외 이유, 금액·조건·공포일과 적용일 구분.
- [수집·재현 기록](collection-plan.md): 수집 범위·원본 해시·재현 절차.

## 공식 출처

| 출처 | 역할·실제 확인 범위 |
|---|---|
| [지자체복지서비스 API 15108347](https://www.data.go.kr/data/15108347/openapi.do) | 현행 서울 복지사업 목록 397건·출산 관련 후보 상세 56건. 과거 이력이나 실제 수급 실적은 아님. |
| [서울 OA-23013](https://data.seoul.go.kr/dataList/OA-23013/S/1/datasetView.do), [OA-23014](https://data.seoul.go.kr/dataList/OA-23014/S/1/datasetView.do) | 같은 원천의 목록·상세 재제공. 독립 자료로 중복 집계하지 않음. |
| 보건복지부 2022·2023·2024 사례집, 국가법령정보센터 조례·연혁, 구청 안내 | 금액·자녀 순위·조건·적용일 교차 확인. 정책 원문 19개를 로컬 보존. |
| [행정안전부 출생등록 통계](https://jumin.mois.go.kr/etcStatBirth.do) | 2018~2024년 공식 CSV 7개. 25개 구·남녀 합계·84개월 완전성 확인. 인증키 불필요. |

출생 통계는 OA-12408의 기존 연결이 비어 있어 같은 원천의 직접 다운로드 경로를 사용했다.
[공공데이터포털 3033249](https://www.data.go.kr/data/3033249/fileData.do)에서 URL·이용허락범위 제한 없음을 확인했다.
원자료·가공 CSV·PDF·인증키는 커밋하지 않는다. 코드·출처 목록·분석 보고서·그림만 공개한다.

## 실행

저장소 루트에서 의존성을 설치한 후 실행한다 (`make install`).

```bash
python cases/ingyeoking13-seoul-birth-support/fetch.py && \
  make flow CASE=cases/ingyeoking13-seoul-birth-support
```

프로젝트 `.venv`를 쓴다면 두 명령의 Python을 `.venv/bin/python`, `make` 옵션을 `PY=.venv/bin/python`으로 지정한다.
기본 `fetch.py`는 사전 등록 확인 → 정책 원문 다운로드·검토 당시 내용 대조 → 정책 집단 확정 확인 →
공식 출생 CSV 다운로드·검증 → 패널·25개 구 기술통계·그림 생성을 수행한다.
이어 `make flow`가 이벤트 스터디·검정·리포트·그림·실행 기록을 만든다.
이전 원본이 있으면 해시와 요청 조건을 대조해 재사용하며, `--offline`은 네트워크 없이 같은 입력으로 재현한다.
원본이 바뀌거나 누락되면 추측·0원/0건 대체 없이 중단한다.

`make flow`는 기존 패널을 재사용하므로 **입력 변경 시 반드시 `fetch.py`부터 실행**한다.
새 원천 스냅샷은 기존 `data/raw/`를 별도 보관한 뒤 다시 수집한다. 해시 불일치를 무시하지 않는다.

현행 복지사업을 별도로 갱신하려면 로컬 `.env`의 `DATA_GO_KR_API_KEY`를 사용한다.

```bash
python cases/ingyeoking13-seoul-birth-support/fetch.py --collect-welfare
```

이 API 호출은 과거 정책·출생 분석 재현에 필수인 단계가 아니다. 키를 코드·출처 URL·PR에 넣지 않는다.

## 사전 등록과 검증

최초 계획 `6e43102`, 정책 집단·원천 경로 확정 `f8af67d`, 수집기 `e19ec14` 이후 실자료를 분석했다.
정책 조사 중 참고 출생 숫자가 노출된 사실과 결과 확인 후 추가한 배정 진단은 각각 명시했다.
빈 폴더에서 공식 정책·출생 원본을 다시 받아 2,100행 변환본과 35행 비교 패널이 일치하는지 확인했다.
테스트는 월 누락·성별 중복·행정구역 불일치·원문 변경·사전 등록 실패 시 중단 등을 검사한다.
원자료 수집 성공과 정책 효과 식별 성공은 별개다.
