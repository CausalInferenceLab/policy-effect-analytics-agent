# 서울시 자치구별 출산지원금 현황 및 변경 이력 연결

기존 `birth-marriage`(출산·혼인 지원) 주제에 서울 자치구의 자체 출산지원금 정보를 연결한다.
현재 기여 범위는 **출처 등록, 사전 분석 계획, 입력 자료 검증·패널 생성 코드**다.
서울 25개 자치구를 조사 대상으로 2023년 첫째아 자체 지원금 증액 구와 유지 구를 비교하도록
`plan.yaml`을 결과 조회 전에 커밋했다. 실제 정책 이력 검증과 실데이터 분석은 아직 완료하지 않았다.

## 수집 범위

- 대상: 서울 자치구가 자체적으로 운영하는 출산장려금·출산축하금·출산양육지원금 사업.
- 지역: 서울 25개 자치구를 조사 대상으로 두되, 확인된 사업부터 수집한다.
- 구분: 국가·서울시 공통 사업은 자치구 자체 지원금과 구분하고 중복 합산하지 않는다.
- 단위: 자치구 × 사업 × 자녀 순위 × 적용기간. 현재 안내만 있으면 확인일 기준 현황으로 기록한다.
- 사업을 찾지 못한 경우는 `확인필요`로 남긴다. 검색 결과가 없다는 이유로 미지원 또는 0원으로 채우지 않는다.

## 공식 출처와 연결 경로

| 출처 | 쓰임 | 확인 상태 |
|---|---|---|
| [한국사회보장정보원 지자체복지서비스 API](https://www.data.go.kr/data/15108347/openapi.do) | 복지사업 목록·상세 정보 수집의 원천 | 설명·이용조건 확인, 실호출 미실시 |
| [서울시 복지서비스 목록 정보, OA-23013](https://data.seoul.go.kr/dataList/OA-23013/S/1/datasetView.do) | 서울시·자치구 관련 사업 찾기 | 데이터셋 설명 확인 |
| [서울시 복지서비스 상세 정보, OA-23014](https://data.seoul.go.kr/dataList/OA-23014/S/1/datasetView.do) | 지원대상·선정기준·지원내용·신청방법 확인 | 데이터셋 설명 확인 |
| 자치구 공식 안내·조례 부칙·공고·보도자료 | 금액·조건·적용일 및 변경 이력 검증 | 사업별 확인 필요 |

확인일: 2026-10-13. 서울 열린데이터광장의 두 자료는 한국사회보장정보원 자료를 재제공하므로 독립된 자료로 중복 집계하지 않는다.
원천 API는 무료 REST/XML 방식이며 개발·운영단계 자동승인으로 안내되어 있다. 과거 연도별 이력 제공 여부는 확인되지 않았다.

출처 연결(Lineage)은 다음 순서로 기록한다.

1. `birth-marriage` 주제 → 카탈로그 데이터셋 `15108347`.
2. 사업 목록 → 동일 사업의 상세 정보 → 자치구 공식 근거.
3. 원문·확인일을 보존한 뒤 지원금액·조건·적용기간을 정리.

변경 이력 확인의 출발점으로 [강남구 2022-12-20 보도자료](https://gangnam.go.kr/board/B_000031/1072842/view.do?mid=ID01_0313)를 사용할 수 있다.
자료에 명시된 발표일과 실제 적용일을 구분하고, 현행 안내를 과거 전체 기간에 소급하지 않는다.

## 기록할 항목

| 항목 | 기록 기준 |
|---|---|
| 자치구·행정구역 코드 | 코드 체계와 기준일을 확인한 뒤 기록 |
| 사업 식별자·사업명·시행 주체 | 원천 식별자를 보존하고 국가·서울시·자치구 구분 |
| 자녀 순위 | 원문 기준 보존. KOSIS의 출산순위와 동일한 정의인지 별도 확인 |
| 금액·주기·기간 | 원 단위 금액, 일시금·월 지급 여부, 지급기간을 각각 기록 |
| 지급 조건 | 거주기간, 자녀 연령, 출생·신고 조건 등 |
| 적용 시작일·종료일 | 근거 문서에 명시된 날짜만 기록. 공포일·안내문 갱신일과 구분 |
| 출처·확인일·검증 상태 | 각 값의 원문 근거와 확인일, 미확인 항목 표시 |

## 현재 상태와 다음 작업

- 완료: `catalog/datasets.yaml` 원천 등록, `plan.yaml` 사전 등록(커밋 `6e43102`), 분석 입력 검증·패널 생성 코드와 합성 입력 단위 테스트.
- 계획의 `data_sources`에 공식 URL·제공기관·이용 조건을 기록했다. 구별 공식 근거를 추가할 때도 이 목록에 먼저 등록하고 커밋한다.
- 남은 작업: 25개 구의 2022~2024년 정책 이력 검증, 공식 출생 통계 CSV 확보, 실자료 `fetch.py` → `make flow` 재현.
- `fetch.py`는 현재 **수동 다운로드 자료를 입력받는 처리기**다. 자동 다운로드 수집기가 완성되었다는 뜻은 아니다.
- 정책 검토표가 없거나 미확인 구가 남아 있으면 출생 CSV를 읽기 전에 중단한다. 누락된 월·비공개 값·동별/구별 중복을 임의로 보정하지 않는다.
- 수급자 수·실제 집행액·개인별 지급 기록은 현재 확인한 API 설명만으로 확보되었다고 볼 수 없다.
- 실제 데이터를 받은 뒤에만 수록 기간·자치구 수·누락 현황을 확정한다.
- 출생 통계와의 결합은 지역·시점·자녀 순위 정의를 확인한 뒤 진행한다. 데이터 연결 자체는 정책 효과의 근거가 아니다.

## 실행

입력 형식과 수집 상태는 [collection-plan.md](collection-plan.md)를 따른다.
원자료를 바꾸거나 계획을 수정했으면 반드시 아래 두 명령을 순서대로 실행한다.
`make flow`만 실행하면 기존 패널을 재사용하므로, 입력 변경 검증을 건너뛰게 된다.

```bash
.venv/bin/python cases/ingyeoking13-seoul-birth-support/fetch.py && \
  make flow PY=.venv/bin/python CASE=cases/ingyeoking13-seoul-birth-support
```

현재는 필수 입력 파일이 없어 수집 단계에서 중단하는 것이 정상이다.
테스트 통과는 실데이터 재현 완료를 뜻하지 않는다. PR의 그림·수치 재현 체크는
공식 자료로 위 실행을 마친 뒤에만 완료로 바꾼다.

원자료·가공 데이터는 저장소에 올리지 않으며, 수집기를 구현할 때 API 키를 코드나 공개 출처 URL에 포함하지 않는다.
