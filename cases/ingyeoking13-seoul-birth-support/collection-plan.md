# 서울 25개 자치구 입력 자료 검증과 수집 상태

## 사전 등록과 범위

분석 계획은 `6e43102`로 출생 통계의 값·추세·추정 결과를 조회하기 전에 커밋했다.
2018~2024년 출생등록을 결과 지표로, 2023-01-01 첫째아 자체 일시금 증액 여부를 비교한다.
25개 구는 조사 모집단이다. 실제 비교에 포함되는 구는 결과값을 읽기 전에 근거에 따라 확정한다.
다른 시점의 변경이나 미확인은 사유를 기록해 제외하며, 미확인을 0원이나 유지 구로 코딩하지 않는다.

## 현행 복지사업 API 수집 결과

- 실행: `.venv/bin/python cases/ingyeoking13-seoul-birth-support/fetch.py --collect-welfare`
- 수집일시: 2026-10-19 01:50:23~01:50:32 KST (2026-10-18 16:50:23~16:50:32 UTC).
- 목록 요청: `ctpvNm=서울특별시`, `numOfRows=100`, 1~4페이지. 전체 397개 사업 식별자는 중복 없이 일치했다.
- 선별: `servNm`, `servDgst`, `lifeNmArray` 중 `출산|출생|신생아|임신|임산부|산모|산후|첫만남`에 해당하는 56건. 모두 상세 응답의 사업 ID·지역과 대조했다.
- 자치구 후보 44건(20개 구), 구 미지정 서울시 사업 후보 11건, 교육청 후보 1건이다. 전체 목록에는 25개 구 모두가 있다.
- 강북구·노원구·양천구·영등포구·서초구는 이 검색 기준에서 후보가 0건이다. 지원 없음·0원·대조군을 뜻하지 않는다.
- `sggNm`에는 자치구 외 `서울특별시교육청`(전체 8건)과 `-`(1건)도 들어온다. 구 미지정(57건)과 함께 별도로 집계했다.
- 상세의 지원대상·선정기준·급여서비스 내용·근거법령·웹사이트를 보존했다. 반복되는 법령·문의처 목록도 유지한다.
- `enfcBgngYmd`는 사업 시작일일 수 있고, `enfcEndYmd`에는 `99991231` 같은 값이 있다. 이를 특정 금액의 적용일·확인된 종료일로 사용하지 않는다.
- 첫째아 현금지원, 다자녀 전용, 장애인가정, 현물·보험·실비 지원 등이 섞여 있다. 정책 집단을 자동 분류하지 않았다.

로컬 완성 스냅샷: `data/raw/welfare/20261018T165023002630Z/`.
원본 XML 60개(목록 4개·상세 56개), JSON 3개(`services.json`, `candidates.json`, `details.json`),
출처·검색 규칙·건수·파일별 SHA-256을 기록한 `manifest.json`이 있다.

## 1. 정책 검토표를 먼저 확정

로컬 `data/raw/policy_review.yaml`에 25개 구를 한 번씩 기록한다. 정책 사실을 추출한 자료이므로 커밋하지 않는다.
검증된 각 공식 근거는 `plan.yaml > data_sources`에도 URL·라이선스를 등록하고 **출생 자료를 조회하기 전에 커밋**한다.
이용 조건을 확인할 수 없는 자료는 임의의 유형으로 채우지 않는다.

다음은 미확인 상태의 입력 예다. `verified`로 바꾸려면 전체 기간의 근거가 있어야 한다.

```yaml
- district: 종로구
  status: unverified
  history_start: "2022-01-01"
  history_end: "2024-12-31"
  first_child_won: {"2022": null, "2023": null, "2024": null}
  conditions_unchanged: null
  change_date: null
  evidence_note: ""
  sources: []
```

- `verified`: 첫째아 자체 일시금, 수급조건, 기간 중 변경 유무를 공식 안내·조례 연혁으로 모두 확인한 상태. `sources` 각 항목에는 `url`, `license`, `checked_on`이 필요하다.
- `excluded`: 다른 시점의 변경·조건 변경·근거 부족 등 사유를 `reason`에 명시한 상태. 결과를 본 뒤 제외하지 않는다.
- `unverified`: 확인 중. 이 상태가 하나라도 있으면 처리기가 중단한다.
- 금액은 원 단위 정수다. 0원은 미지원의 공식 근거가 있을 때만 쓴다.
- 유지 구: 세 연도 금액이 동일하고 `change_date: null`, 지급조건 동일.
- 증액 구: 2022년보다 2023년 금액이 크고 2024년까지 유지, `change_date: "2023-01-01"`, 지급조건 동일.
- 연중 변경·여러 번 변경·분할 지급을 단순 연말 금액으로 축약하지 않는다. 이번 설계에서 제외하거나 결과 조회 전에 계획을 수정한다.

## 2. 공식 출생 CSV와 출처 기록

정책 검토를 마친 뒤 공식 통계를 내려받는다. 원본 파일은 로컬 `data/raw/`에 보존하고,
열 추출·자치구 합계 선택·열 이름 변경 절차를 기록해 `data/raw/births.csv`로 준비한다.
실제 파일을 확보한 뒤 이 변환을 자동화하고 원본 해시도 기록해야 재수집까지 완성된다.

| 열 | 의미 |
|---|---|
| `district` | 자치구 이름. 서울시 총계와 동별 행 제외 |
| `year` | 2018~2024 정수 연도 |
| `month` | 1~12 정수 월 |
| `births` | 신고기준 출생자수의 남녀 합계. 분리된 성별 행 중복 금지 |

25개 구 × 7년 × 12개월 = 2,100행이 필요하다. `-`, 비공개, 결측을 0으로 바꾸지 않는다.
자치구 합계가 없으면 동 합산의 완전성과 행정구역 변경을 별도 검증한 뒤 변환해야 한다.

`data/raw/births.source.json`에는 `url`(plan 첫 번째 출처와 동일), `license`(`KOGL-1`),
`retrieved_at`(다운로드 일시), `sha256`(births.csv 바이트 해시), `preparation`(원본 경로·원본 해시·추출 절차)을 기록한다.
해시만으로 출처의 진위나 수동 검토가 증명되는 것은 아니다. 공식 원문 대조가 필요하다.

## 3. 실행과 완료 기준

저장소 루트에서:

```bash
.venv/bin/python cases/ingyeoking13-seoul-birth-support/fetch.py && \
  make flow PY=.venv/bin/python CASE=cases/ingyeoking13-seoul-birth-support
```

처리기는 정책 검토 → 출처·해시 → 월별 완전성 → 연간 합계 → 로그 지표 순서로 검사한다.
성공 시 `data/panel.csv`, `data/panel.source.json`을 생성한다. 기존 패널을 재사용하는 `make flow` 특성상
입력을 바꿀 때마다 반드시 처리기를 먼저 실행하고, 실패하면 분석을 진행하지 않는다.

다른 사람이 같은 공식 원자료로 위 실행을 마쳐 `report.md`, `figures/`, `run_manifest.json`을 재현하고,
`discussion.md`의 한계와 함께 결과를 확인한 뒤에만 PR의 재현 체크를 완료한다.
합성 입력 단위 테스트나 데이터 부족으로 중단한 실행은 이 완료 기준을 충족하지 않는다.
