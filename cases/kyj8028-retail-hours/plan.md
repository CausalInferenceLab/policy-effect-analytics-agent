## 1. 목적과 완료 기준

대형마트 의무휴업일의 평일 전환을 사례로, 자료 수집·품질 검사·추정·반증 분석·보고서 생성을 연결하는 분석 파이프라인을 구축한다. 7주 동안 이 흐름을 자동화하고, 정책 이력 검토와 분석 변경을 기록하는 절차를 마련한다. 정책 효과를 해석하는 데 필요한 세부 근거는 이후 보강한다.

과정 종료 시 다음 기준을 충족하는 것을 목표로 한다.

- 사례별 실행 설정과 수집 코드로 분석용 패널을 다시 생성할 수 있다.
- 누락·중복·코드 연결 오류를 검사하고, 추정 진행·중단 사유를 기록한다.
- 추정, 가짜 시행일 검정, 판정 규칙 적용과 보고서 생성을 연속 실행한다.
- 데이터 출처·수집 시점·실행 설정·검사 결과를 남기고, 다른 참여자가 README에 따라 같은 입력과 설정으로 결과를 재현한다.
- 미확인 정책·측정 조건이 결과 해석에 미치는 한계를 보고서에 표시한다.

실자료로 실행할 수 없으면 원인과 보완할 사항을 기록하고, 시뮬레이션 데이터로 전체 흐름을 검증한다. 시뮬레이션에는 `synthetic_data: true`와 출처를 표시한다. 파이프라인 검증 여부와 실자료 분석 여부는 따로 보고한다.

## 2. 연구 질문과 초기 분석 범위

연구 질문은 다음과 같다.

> 동대문구의 대형마트 의무휴업 평일 전환 이후, 골목상권 식품판매 관련 업종의 분기 추정매출은 비교 자치구와 비교해 어떻게 달라졌는가?

초기 구현은 동대문구 단일 처치 사례와 서울 내 비교 후보를 대상으로 한다. 결과는 제한된 지역·업종·기간의 탐색적 추정으로 제시하며, 증가와 감소 모두 검토한다. 전통시장 전체, 마트 인접 점포 전체, 개별 소상공인의 효과로 일반화하지 않는다.

| 항목 | 초기 구현 기준 |
|---|---|
| 분석 단위 | 자치구 × 분기 |
| 처치 지역 | 동대문구 |
| 자료 범위 | 2021Q1~2024Q4 |
| 분석에서 제외할 분기 | 2023Q4: 발표에 따른 선반영 가능 구간, 2024Q1: 전환·일부 점포 유예 구간. 모든 지역에 동일 적용 |
| 사전·사후 구간 | 사전 2021Q1~2023Q3(11분기), 사후 2024Q2~Q4(3분기) |
| 주지표 | 골목상권의 육류판매·수산물판매·청과상·반찬가게 분기 추정매출 합계의 자연로그 |
| 업종 코드 | `CS300007`, `CS300008`, `CS300009`, `CS300010` |
| 보조 출력 | 동일 범위의 원 단위 매출 합계와 업종별 기술통계 |

매출 합계가 0이거나 구성 자료가 누락되면 원인을 검사한다. 로그 계산을 위해 임의로 1원을 더하거나 누락을 0으로 치환하지 않는다. 공식 업종 대응표에는 도매업도 포함되어 있으므로 순수 소매업만의 지표라고 설명하지 않는다. 슈퍼마켓은 기업형 슈퍼마켓(SSM) 혼입 때문에 주지표에서 제외한다. 업종 정의는 [공식 분류표](https://golmok.seoul.go.kr/images/100_v3.pdf)를 따른다.

## 3. 정책 이력과 비교집단 관리

동대문구는 [2023년 12월 29일 행정예고](https://www.ddm.go.kr/www/selectEminwonWebView.do?key=3291&notAncmtMgtNo=16726) 후 [2024-16호 고시](https://www.ddm.go.kr/www/selectEminwonWebView.do?key=3291&notAncmtMgtNo=16863)를 통해 일요일 의무휴업 지정을 해제하고 협약에 따른 둘째·넷째 수요일 자율휴무로 전환했다. 효력일은 2024년 1월 29일이며 일부 점포는 2월 26일부터 적용된다. 정책 효력일과 분석상 첫 완전 노출 분기인 2024Q2를 구분한다.

비교 후보는 서울의 나머지 자치구 중 서초·중구·관악을 제외한 지역으로 설정한다. 서초는 평일 전환과 후속 영업시간 완화, 중구는 2024년 중 전환, 관악은 2024년 말 전환 확정에 따른 선반영 가능성을 고려한다. 성동은 점포별 평일 휴업 예외와 전환 추진 이력 확인 전까지 초기 비교군 편입을 보류한다. 남은 20개 구는 검토 후보이며 전 기간 미전환을 확인한 확정 대조군을 의미하지 않는다.

정책 목록에는 자치구·대상 점포·발표일·효력일·일시 예외·후속 변경·출처·확인 수준을 기록한다. 실행에 사용할 비교 지역 목록과 확인 수준은 매출 결과 열람 전에 고정한다. 확인이 부족한 지역을 포함하는 탐색 실행에서는 그 가정을 명시하고 인과적 판정을 보류한다. 결과의 방향이나 유의성에 따라 비교 지역을 선택하지 않는다.

동일 도시의 공통 충격을 공유한다는 점을 비교 근거로 삼되, 정책 도입의 자기선택과 지역 간 소비 이동을 한계로 다룬다. 평일 전환 연계 지원사업은 [서울시의회 결산 기록](https://mas.smc.seoul.kr/record/recordView.do?key=8eee9ad6c34937762f150a6f45cd72764c6ae28cc71e710e19b7efc806f5ebd847d57163f338eb45)에서 확인된다. 개별 집행일이 미확인인 동안에는 휴업 요일 변경만의 순수 효과라고 해석하지 않는다.

## 4. 자료원과 수집 설계

| 자료원 | 용도 | 현재 확인 범위 |
|---|---|---|
| 자치구 고시·공식 보도자료·의회 기록 | 정책 목록과 지역별 처치 분류 | 동대문 고시 등 일부 확인, 전체 이력은 후속 보강 |

매출은 카드결제 자료를 보정한 추정 지표다. 제공기관은 2024년 공간 단위 개편과 2021년 이후 자료의 재제공을 안내하고 있다. 확인한 공간 파일은 2023년 작성본으로, 최신 매출과의 경계·버전 호환성은 아직 미확인이다. 코드 연결 성공만으로 시계열 측정의 일관성이 입증되었다고 보지 않는다.

`fetch.py`는 원자료 취득, 열 이름·코드·분기 정규화, 골목상권과 4개 업종 선택, 자치구 연결, 분기별 집계, 정책 목록 결합을 수행하도록 작성한다. 한 번 확보한 입력으로 재실행할 수 있도록 수집 시점·원본 파일 식별 정보·해시·변환 규칙을 기록한다. 갱신 자료를 받으면 기존 입력과 구분하고 변경 내역을 남긴다.

자료별 이용 조건을 실행 설정과 README에 명시한다. 원자료·가공 데이터와 인증 정보는 저장소에 포함하지 않는다. 공간 연결이 불가능하거나 모호한 경우 면적 비례 배분이나 임의 연결로 대체하지 않는다.

## 6. 품질 검사와 실패 처리

분기는 `2021Q1=0`부터 실제 달력 간격대로 정수화한다. 제외 분기를 압축해 재번호하지 않는다. 기본 패널 열은 `gu_code`, `quarter_idx`, `treated`, `sales_krw`, `log_sales`로 구성하며 처치집단 표시 `treated`는 도입 전후에 동일하게 유지한다.

| 구분 | 검사 내용 |
|---|---|
| 공통 자동 검사 | 필수 열, 결측, 정수 시간축, 단위×시점 중복, 사전·사후 관측과 처치·비교집단 존재 |
| 사례별 추가 검사 | 업종·상권 코드 연결 누락, 자치구 대응의 유일성, 모든 구의 관측 분기 집합 일치, 제외 분기와 처치 표시 일관성 |
| 집계 검증 | 원자료와 집계 합계 대조, 0과 누락의 구분, 로그 변환 가능 여부, 필요한 업종·상권 구성의 누락 |
| 근거 검토 | 공간 버전, 정책 이력, 지원사업·후속 정책의 확인 수준과 해석 제한 |

중복·연결 실패·해결되지 않은 결과 결측 등 입력 오류가 있으면 실자료 추정을 중단하고 검사 결과를 남긴다. 정책 이력이나 공간 버전이 미확인인 경우에는 계산이 가능하더라도 인과효과 판정을 보류한다.

실자료 분석이 중단되면 동일한 열 구조의 시뮬레이션으로 정상 실행과 오류 시 중단 여부를 확인한다. 실자료와 시뮬레이션의 입력·설정·출력은 분리하고 보고서에도 구분해 표시한다.

## 7. 초기 추정·반증·판정 설정

자치구와 분기 고정효과를 포함한 이벤트스터디를 초기 방법으로 사용한다. 분석상 시작점은 2024Q2(`treat_time=13`), 기준 분기는 2023Q3(`ref_period=-3`), 상대시점 범위는 `[-13, 2]`로 설정한다. 공변량 없이 시작하며 주 추정량은 사후 3분기 계수의 단순평균이다. 제외 분기의 빈 상대시점은 추정에서 제거한다.

| 항목 | 초기 기준 |
|---|---|
| 불확실성 | 양측 유의수준 0.05, 자치구 단위 추론 |
| 소수 처치 | 공통 구현의 무작위화 추론 사용 조건 확인, 단일 처치의 한계로 최상 판정도 조건부 |
| 사전추세 | 결합검정 유의수준 0.10, 기각 시 판단 불가 |
| 가짜 시행일 | 2023Q1, `shift=5`; 실제 분석 시작 전 자료만 사용, 유의수준 0.10 |
| 기간 기준 | 사전 최소 8분기, 사후 최소 3분기. 미달 시 초기 효과 해석 보류 |
| 군집 수 | 20개 미만이면 조건부로 판정하고 검정력 한계 기록 |
| 신뢰구간 | 0을 포함하면 불확실로 해석, 효과가 없다고 단정하지 않음 |

위 수치는 이 사례의 초기 운영 기준이다. `plan.yaml`이 지원하는 조건은 `abstention`과 `thresholds`에 반영하고, 사후 기간·근거 미확인 등 스키마 밖 조건은 사례별 검사와 해석 기록으로 관리한다. 가짜 시행일 검정에서 유의한 결과가 나오면 조건부로 낮춘다. 시차 도입을 단순 동시 도입 모형에 혼합하면 판단 불가로 처리한다.

무작위화 추론의 반복 횟수는 독립적인 정책 지역 수를 늘리지 않는다. 사전추세 검정 통과도 평행추세나 정책 배정의 교환가능성을 입증하지 않는다. 인접 지역 제외 민감도 분석은 확장 항목으로 두고, 적용 시 경계 자료와 제외 목록을 사전에 고정한다. 현재 공통 파이프라인에서 자동 실행되지 않는 검사는 사례별로 구현·검증한 뒤 포함한다.

## 8. 제출·변경 관리와 후속 과제

프로젝트 범위와 일정은 `plan.md`에, 실행 설정과 사전등록 기준은 `plan.yaml`에 기록한다.

[참여 가이드](../../docs/ops/mentee-guide.md)에 따라 케이스 제안, 정책 목록, 시행 시점·대상·측정 항목 확인 결과를 정리한 뒤 계획 PR을 준비한다. 초기 실행의 비교 후보 목록·확인 수준·자료 처리 가정·판정 규칙을 [계획 작성 가이드](../../docs/strategy/plan-guide.md)와 [스키마](../../core/schema/plan.py)에 맞춰 YAML에 반영하고, 매출 결과 자료를 열기 전에 커밋·PR한다. 미확인 정책 날짜를 임의 값으로 채우지 않는다.

계획 PR → 수집·분석 PR → 리포트 PR 순서로 단계별 제출한다. 관련 검사와 `make check` 결과를 기록하고, 실행하지 못한 검사는 이유를 명시한다. 리뷰 1명 승인과 CI 통과 후 squash merge 절차를 따른다. 공통 모듈 변경이 필요하면 먼저 이슈로 논의한다.

결과 확인 후 기간·지역·업종·방법을 바꾸면 변경 이유와 영향을 커밋 기록 및 `discussion.md`에 남긴다. 초기 결과를 후속 설계의 사전등록 결과로 다시 표시하지 않는다.

| 후속 보강 항목 | 초기 과정에서 관리할 내용 | 보강 후 활용 |
|---|---|---|
| 지원사업 집행일·대상지 | 동시 정책 가능성과 근거 공백 표시 | 정책 효과 범위와 기간 재검토 |
| 비교구 전체 이력·점포 예외 | 후보 목록과 확인 수준 고정 | 검증된 비교집단 구성 |
| 공간 경계·코드 버전 호환성 | 연결 검사와 측정 한계 표시 | 동일 기준의 시계열 확보 |
| 추가 기간·업종·분석 방법 | 초기 구현 범위와 분리 | 별도 계획에 따른 확장 분석 |

추가 근거 수집은 7주 과정 이후에도 이어간다. 근거가 부족한 분석은 판단 불가로 보고한다. 본 프로젝트는 학습·연구용 오픈소스 분석이며 정부·공공기관의 공식 평가가 아니다.
