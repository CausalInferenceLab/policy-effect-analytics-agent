## 관측 매출 탐색 분석 재현

저장소 루트에서 개발 환경을 설치한 뒤 실행한다. API 키는 필요하지 않다. 처음에는 다음 명령으로 원본을 취득한다. 성공하면 출력된 스냅샷 경로를 아래 재현 명령의 `--snapshot`에 넣는다. 실패 시 다음 단계로 진행하지 않는다.

```bash
.venv/bin/python cases/YoungjaeKang-retail-hours/fetch.py fetch
```

저장된 스냅샷으로 재현할 때는 `fetch`가 출력한 경로를 지정한다. 아래 경로는 이번 분석에서 사용한 로컬 스냅샷이며 저장소에 포함되지 않는다.

```bash
MPLCONFIGDIR=/tmp/retail-matplotlib .venv/bin/python cases/YoungjaeKang-retail-hours/visualize.py \
  --snapshot cases/YoungjaeKang-retail-hours/data/raw/sales/20261021T120614Z && \
MPLCONFIGDIR=/tmp/retail-matplotlib make flow PY=.venv/bin/python CASE=cases/YoungjaeKang-retail-hours
```

`visualize.py --snapshot <경로>`는 원본을 다시 검사하고 관측 패널과 진단 그림 2개를 생성한다. 실패 시 `&&` 뒤의 분석은 실행되지 않는다. 이어지는 `make flow`가 기본 그림과 discussion의 추가 그림 링크를 포함한 보고서를 재생성한다.

`fetch`는 새 원본 취득 후 관측 패널을 생성한다. `build-observed`는 해시를 확인한 기존 원본으로 재생성하며 기본 명령도 동일하다. `build`는 원래 전체매출 지표의 보류 진단만 수행하고 종료 코드 2를 반환한다. `simulate`는 별도 폴더에서 합성 입력으로 실행 흐름을 검사한다.

공통 `make flow`는 기존 패널이 있으면 수집 검사를 건너뛴다. 따라서 위 연결 명령을 사용하며, 실패 후 `make flow`만 따로 실행하지 않는다. 새 다운로드는 제공기관 수정 때문에 기존 원본과 다를 수 있다. 동일 스냅샷 재현과 새 취득 결과는 구분한다.

- `data/raw/sales/<snapshot>/`: 원본 ZIP·제공 페이지·조회 조건·취득 시각·해시.
- `data/observed-full.csv`, `data/panel.csv`: 전체 336행·추정 315행. `gu_code`에는 이 사례의 구명 문자열을 사용한다.
- `data/panel.source.json`: 입력·코드·계획·명단·패널 해시 및 측정 한계.
- `data/sales-audit/<snapshot>/`: 업종별 관측 공백, 관측 수·진입·이탈, 품질 진단. 부재 금액은 0으로 채우지 않는다.
- `report.md`, `figures/`, `flow_log.json`, `run_manifest.json`: `make flow` 자동 생성. 해석 수정은 `discussion.md`에 반영한 뒤 재생성한다.

원자료·가공 데이터·인증정보는 커밋하지 않는다. 매출·영역 등 서울 자료는 공공누리 1유형이며, 인구는 공식 제공목록의 이용허락범위 제한 없음을 확인했다. 자료별 출처·이용 조건은 `plan.yaml`에 기록했다.

## 특성자료 수집·검사

저장소 개발 환경 설치 후 루트에서 실행한다. API 키나 추가 패키지 설치는 필요하지 않다.

```bash
.venv/bin/python cases/YoungjaeKang-retail-hours/fetch_characteristics.py fetch
# 위 명령이 출력한 snapshot 경로를 지정해 네트워크 없이 재검사한다.
.venv/bin/python cases/YoungjaeKang-retail-hours/fetch_characteristics.py build --snapshot <snapshot 경로>
.venv/bin/python -m pytest cases/YoungjaeKang-retail-hours/test_fetch_characteristics.py
make check PY=.venv/bin/python
```

기본 `fetch`는 가구·면적·시장·점포·영역·인구의 6개 자료를 새 스냅샷에 받는다. `--sources population --output <별도 폴더>`처럼 일부만 지정할 수도 있다. 이때 선택하지 않은 자료는 미수집으로 표시되며 이전 결과와 자동 병합하지 않는다. 전체 표는 6개 자료가 포함된 스냅샷으로 재생성한다.

원본은 `data/raw/characteristics/<수집시각-고유번호>/<자료원>/`에 보존한다. 기본 출력은 `data/characteristics/`에 갱신하며 `--output`으로 다른 폴더를 지정할 수 있다. 원본·가공 CSV·출처 기록·검사 결과는 모두 Git 제외 대상이다. 새로 다운로드하면 제공기관의 과거 자료 수정에 따라 값이 달라질 수 있다. 저장된 스냅샷으로 재생성하는 것과 구분한다.

## 산출물과 검사

- `review.csv`: 25개 구의 인구·고령인구·가구·시장 등 비교표. 열에 단위와 시점을 표시하고 보류 사유를 기록한다.
- `values.csv`: 25개 구×20개 지표의 500행. 값·분자/분모·상태·출처를 보존한다. 정책 이력·대형마트/SSM 이력·인접성은 별도 조사표에서 관리한다.
- `sources.json`: 공식 URL·조회 조건·취득 시각·원본 경로와 해시·변환 코드 커밋 및 파일 해시. 인구 다운로드는 서버 파일명을 기록하지 못한 대신 응답 경로·로컬 파일명·해시로 식별한다.
- `quality.json`: 자료별 검사 결과와 상태 집계. `partial`은 미해결 항목이 있다는 뜻이다. 종료 코드 0은 입력 오류 없이 부분 산출했음을 뜻하며 전체 자료 완성을 뜻하지 않는다. 입력 오류는 1로 반환한다.

[fetch_characteristics.py](fetch_characteristics.py)가 공개 CSV/XLSX/ZIP을 취득하고 원본 해시를 검증한다. [characteristics_files.py](characteristics_files.py)는 시장 형태·구별 총계·중복 후보, 점포의 분기·업종·수치 관계와 영역 코드 연결을 검사한다. XLSX/DBF는 해당 공개 파일 구조만 지원하며 범용 파서가 아니다. 시장 총계 수식은 캐시 값과 상세 행 수를 대조하고 시장의 점포 수 열은 사용하지 않는다.

[characteristics_population.py](characteristics_population.py)는 2022-12·등록구분 전체·남녀 합계·1세 단위 조회를 확인한다. 0~99세와 100세 이상 합계, 총인구와 연령구간 인구, 25개 구의 연령별 합계와 서울 합계를 대조한다. 고령인구는 65세 이상이며 60~64세는 포함하지 않는다.

서울통계의 `gu_code`는 통계표 분류 코드다. 행안부 10자리 주민등록 행정기관 코드는 `source_gu_code`와 코드 체계로 별도 보존한다. 공식 구명 목록을 대조해 연결하며 두 코드 체계를 같다고 간주하지 않는다. 미수집·비공개·미해결·분모 0을 숫자 0으로 채우지 않는다.

## 현재 결과

2026-10-13 실제 다운로드와 오프라인 검사를 마쳤다. **500행 중 222개 값 확인, 278개 보류**다. 인구·가구·연간 면적은 25개 구, 시장 개수는 22개 구, 시장 존재 여부는 25개 구에서 확인했다. 이 결과는 정책 효과 추정이나 최종 비교군 확정이 아니다.

시장 집계는 원파일 ‘형태’가 건물형·골목형·혼합형인 행을 포함하고 상점가·지하도상가는 제외한다. 법적 인정·등록 지위를 새로 판정하지 않는다. 상세 369행과 구별 총계를 대조했으며 포함 대상 296행은 중복 후보 해결 전의 행 수라서 서울의 고유 시장 수로 보고하지 않는다. ‘동대문’ 구명은 상세 주소의 ‘동대문구’와 대조했다. 노원의 연번 반복 때문에 연번을 고유 식별자로 쓰지 않는다.

## 검증

사례 테스트는 기본 pytest 탐색 범위 밖이므로 별도로 실행한다.

```bash
.venv/bin/python -m pytest cases/YoungjaeKang-retail-hours -q
make check PY=.venv/bin/python
.venv/bin/python scripts/check_licenses.py
.venv/bin/python scripts/check_lineage.py
```

2026-10-21 기준 사례 테스트 76개와 `make check`가 통과했다(2개 skip, 기존 시간축 경고). 실제 원본에서 336/315행과 공통 품질검사 11개, 6단계 실행을 확인했다. 2026-10-23 최신 main 반영 후 사례 76개와 `make check`를 다시 통과했다(2개 skip, 기존 시간축 경고). 라이선스·계보·format·diff 검사도 통과했고, 동일 실제 스냅샷의 패널과 추정치를 재현했다. 후속 보고서에서는 시각화 검사 6개를 추가해 사례 테스트가 82개다. 첫 분기 진입·이탈의 결측 보존, 미관측 금액의 0 대체 차단, 진단 격자·진입이탈 불일치와 원본 검사 실패 시 중단을 검사한다. 다른 참여자의 재현은 아직 확인하지 않았다.

2026-10-28 최신 main을 반영해 보존 스냅샷으로 관측 패널·추가 그림·분석을 재생성했다. 패널과 추가 그림 2개의 해시는 기존과 같고, 추정 결과는 수치 허용오차 내에서 일치한다. 사이트 빌드에서 한 문장 해석과 계획 변경 이력이 표시됨을 확인했다. 새 다운로드나 타 참여자 독립 재현을 수행한 것은 아니다.
