## 1. 목적과 완료 기준

동대문구의 대형마트 의무휴업일 변경을 주제로, 자료를 모으고 검사한 뒤 분석과 보고서 작성까지 이어서 실행할 수 있도록 만든다. 7주 동안 이 과정을 자동화하면서 정책 자료를 검토한 내용과 분석 계획을 바꾼 이유도 기록한다. 아직 확인하지 못한 정책 근거는 추가로 조사한다.

이 사례의 기여는 동대문 골목상권의 식품판매 관련 업종을 공개 자료로 분석하고, 정책 근거 확인부터 자료 집계·검사·추정까지 다른 사람이 재현할 수 있게 만드는 데 있다. 효과의 크기나 통계적 유의성을 완료 기준으로 삼지 않는다. 판단을 보류하는 경우에도 그 이유와 추가로 필요한 근거를 남긴다.

과정이 끝날 때는 다음 작업이 가능해야 한다.

- 저장한 설정과 수집 코드로 자치구·분기별 분석 자료를 다시 만든다.
- 자료 누락·중복·코드 연결 오류를 검사하고, 분석을 진행하거나 멈춘 이유를 남긴다.
- 효과 추정, 가짜 시행일 검정, 판단 기준 적용, 보고서 작성을 이어서 실행한다.
- 데이터 출처·수집 시점·실행 설정·검사 결과를 남기고, 다른 참여자가 README에 따라 같은 입력과 설정으로 결과를 재현한다.
- 확인하지 못한 정책 이력이나 자료 기준 때문에 결과를 어디까지 해석할 수 있는지 보고서에 적는다.
- 원 단위 매출 추세와 이벤트스터디 그림, 업종별 매출·구성비·관측 누락 표를 함께 제시한다. 업종별 표는 기술통계이며 별도의 인과효과 추정으로 해석하지 않는다.

실제 자료로 분석할 수 없으면 막힌 이유를 적고 시뮬레이션 데이터로 코드가 끝까지 동작하는지 확인한다. 시뮬레이션에는 `synthetic_data: true`와 출처를 표시한다. 코드가 동작하는지 확인한 것과 실제 자료로 분석을 마친 것은 구분해서 보고한다.

## 2. 연구 질문과 분석 범위

[선행연구 노트](research-notes.md)에는 평일 전환, 의무휴업 당일의 매출, 대형마트 폐점, 해외 규제 연구를 구분해 정리했다. 평일 전환 연구는 정책 질문을, 서울시 자료를 사용한 폐점 연구는 상권 연결과 자료 기준 확인을 참고한다. 기존 연구의 업종·공간·시간 단위가 서로 다르므로 효과의 부호나 크기를 이번 분석의 정답으로 삼지 않는다.

마트와 동네 점포는 같은 상품을 두고 경쟁하는 동시에 방문객을 공유할 수 있다. 두 경로 중 어느 쪽이 큰지는 업종과 지역에 따라 달라질 수 있으므로 예상 방향은 미정으로 둔다.

연구 질문은 다음과 같다.

> 동대문구의 대형마트 의무휴업 평일 전환 이후, 골목상권 식품판매 관련 업종의 분기 추정매출은 비교 자치구와 비교해 어떻게 달라졌는가?

첫 분석에서는 동대문구 한 곳과 서울의 다른 자치구를 비교한다. 매출이 늘었는지 줄었는지 모두 살펴보되, 결과는 아래 지역·업종·기간에 한정해 탐색적으로 해석한다. 전통시장 전체나 마트 주변 모든 점포, 개별 소상공인에게 같은 변화가 있었다고 설명하지 않는다.

분석 대상은 전환 이후의 분기 총매출 변화다. 특정 일요일의 대체소비, 요일별 구매 시점 이동, 개별 소비자의 선택을 따로 식별하지 않는다. 고용·이익·소비자 후생을 포함한 규제 전체의 편익과 비용도 평가 범위에 포함하지 않는다.

| 항목 | 분석 기준 |
|---|---|
| 분석 단위 | 자치구 × 분기 |
| 처치 지역 | 동대문구 |
| 자료 범위 | 2021Q1~2024Q4 |
| 분석에서 제외할 분기 | 2024Q1: 전환·일부 점포 유예 구간. 모든 지역의 효과 추정에서만 제외하고 원자료·전체 분기 집계에는 보관하며 추세 그림에 전환기로 표시 |
| 사전·사후 구간 | 사전 2021Q1~2023Q4(12분기), 사후 2024Q2~Q4(3분기) |
| 주지표 | 골목상권의 육류판매·수산물판매·청과상·반찬가게 분기 추정매출 합계의 자연로그 |
| 업종 코드 | `CS300007`, `CS300008`, `CS300009`, `CS300010` |
| 보조 출력 | 동일 범위의 원 단위 매출 합계와 업종별 기술통계 |

매출 합계가 0이거나 구성 자료가 누락되면 원인을 검사한다. 로그를 계산하기 위해 임의로 1원을 더하거나 빠진 값을 0으로 채우지 않는다. 공식 업종 대응표에는 도매업도 포함되어 있으므로 순수 소매업만의 지표라고 설명하지 않는다. 슈퍼마켓에는 기업형 슈퍼마켓(SSM)이 섞여 있어 주지표에서 제외한다. 업종 정의는 [공식 분류표](https://golmok.seoul.go.kr/images/100_v3.pdf)를 따른다.

네 업종은 대형마트 취급 식품과의 관련성 및 공개 자료의 코드 구분을 기준으로 선정했다. 반찬가게 코드에는 일부 가공식품·조미료·커피 및 차 도매도 포함되므로 코드명만으로 점포 성격을 판단하지 않는다. 주지표는 네 업종의 합계로 유지하고, 업종별 매출과 구성비를 함께 제시해 변화가 특정 업종에 집중되는지 살펴본다. 업종 범위는 자료 정의와 수집 가능성을 근거로 정하며, 추정 결과의 방향에 따라 포함 여부를 바꾸지 않는다.

## 3. 정책 이력과 비교 지역

동대문구는 [2023년 12월 29일 행정예고](https://www.ddm.go.kr/www/selectEminwonWebView.do?key=3291&notAncmtMgtNo=16726) 후 [2024-16호 고시](https://www.ddm.go.kr/www/selectEminwonWebView.do?key=3291&notAncmtMgtNo=16863)를 통해 일요일 의무휴업 지정을 해제하고 협약에 따른 둘째·넷째 수요일 자율휴무로 전환했다. 효력일은 2024년 1월 29일이며 일부 점포는 2월 26일부터 적용된다. 분석에서는 전환을 마친 뒤 처음 맞는 온전한 분기인 2024Q2를 시작점으로 삼는다. 고시의 효력일과는 구분한다.

비교 후보는 서울의 나머지 자치구 중 서초·중구·관악을 제외한 지역으로 설정한다. 서초는 평일 전환과 후속 영업시간 완화, 중구는 2024년 중 전환, 관악은 2024년 말 전환 확정에 따른 선반영 가능성을 고려한다. 성동은 일부 점포의 평일 휴업과 전환 추진 이력을 확인할 때까지 비교 지역에 넣지 않는다. 남은 20개 구는 점포 예외 확인의 한계를 수용한 탐색 비교군으로 고정한다. 분석 기간 내내 일요일 휴업을 유지했다고 전수 확인한 것은 아니다.

현재 자치구별 근거와 미확인 사항은 [정책 확인표](policy-verification.md)에 정리했다. 목록에는 구별 대상 점포, 발표일과 효력일, 일시적인 예외, 이후 변경 사항과 출처를 더해 나간다. 실행에 사용할 비교 지역 목록과 확인 수준은 매출 결과 열람 전에 고정한다. 이력이 불분명한 지역을 포함해 계산하면 그 사실을 밝히고, 결과를 탐색적으로만 제시한다. 정책 효과에 대한 판단은 보류한다. 결과의 방향이나 유의성에 따라 비교 지역을 선택하지 않는다.

서울 안에서는 경기나 계절 변화의 영향을 함께 받는다는 점을 비교의 근거로 삼는다. 다만 휴업일을 바꾼 지역은 원래 상권 사정이 달랐을 수 있고, 소비자가 다른 구로 이동했을 수도 있다. 평일 전환 연계 지원사업은 [서울시의회 결산 기록](https://ms.smc.seoul.kr/attach/record/SEOUL/appendix/a11/A0068374.pdf)에서 확인된다. 지원사업이 실제로 언제 진행됐는지 확인하기 전에는 매출 변화가 휴업 요일 변경만의 효과라고 해석하지 않는다.

비교 후보별로 동대문과의 인접 여부와 소비 이동 가능성을 기록한다. 자치구 전체 집계에는 마트에서 먼 상권도 포함되므로 결과를 마트 바로 주변의 효과로 해석하지 않는다. 인접 지역 제외 분석은 별도 사전 계획을 마련하기 전까지 초기 분석에 추가하지 않는다.

### 2026-10-20 선정 검토 결과

[구별 선정 근거](control-review.md)에 정책 근거·특성 차이·수용한 한계를 기록하고 비교군 20개 구를 고정했다. 서초·중구·관악 제외, 성동 보류를 유지한다. 전 점포 예외 확인을 완료 조건에서 제외한 이유와 해석 범위는 아래에 명시한다.

서울시의회 결산 검토보고서 PDF 46~47쪽에서 골목상권 특화지원의 2024년 12월 보조금 교부를 확인했다. 동대문 내 실제 공사·시설 설치 날짜와 대상지는 미확인이다. 교부일을 처치일로 사용하지 않고 추정 기간·방법·업종을 유지한다. 명단과 이유를 매출 열람 전에 커밋·PR한다.

### 비교군 선정 기준 — 전수 조사 전에 정할 사항

**2026-10-20 변경:** 사용자가 전 점포 예외의 완전한 확인은 어렵다는 점을 수용하고 한계를 명시한 뒤 진행하기로 했다. 종전의 ‘전 기간·전 점포 이력 확인 후 편입’ 조건을 공개 근거에 기반한 탐색 비교로 변경한다. 매출 원자료 열람·효과 추정 전의 결정이다. 과거 엄격 기준의 편입 확인 0개는 현재 명단을 뜻하지 않는다.

조사 범위는 서울 25개 구다. 동대문을 처치로, **종로·용산·광진·중랑·성북·강북·도봉·노원·은평·서대문·마포·양천·강서·구로·금천·영등포·동작·강남·송파·강동 20개 구**를 비교군으로 고정한다. [comparison-groups.yaml](comparison-groups.yaml)이 명단 원본이다. [선정 근거](control-review.md)에 구별 판단과 수용한 공백을 기록한다.

| 항목 | 확정한 처리 |
|---|---|
| 기간 내 정기 평일 전환 | 확인된 서초·중구는 제외. 이후 새 근거가 확인되면 명단을 조용히 바꾸지 않고 계획 변경으로 기록 |
| 구체적 전환 발표·협약 | 실제 시행일과 구분. 관악은 2024년 12월 전환 확정 기록에 따라 선반영 가능성으로 제외 |
| 구체적 충돌 단서 | 성동은 정기 수요일 휴업·2024년 전환 추진 보도에 대응하는 정책 상태가 모호해 보류. 단순 논의와 실제 체결은 구분 |
| 점포 예외·기본 처분의 공백 | 모든 점포의 2021~2024 이력을 완전히 복원하는 조건은 해제. 공백을 명시하고 분석 가정으로 수용하되 미전환 확인 완료로 표현하지 않음 |
| 명절 한시 변경·농수산물 규제 제외 | 정기 평일 전환과 구분. 확인된 점포·기간을 기록하며 이 예외만으로 구 전체를 자동 제외하지 않음 |
| 자료가 적은 구 | 동작 등의 근거 부족을 공개하고 기존 20개 후보 전체를 포함. 검색 결과 없음은 미전환의 증거가 아니며 정책 오분류 가능성을 한계로 남김 |
| 해석 | 정책 이력 공백이 남는 결과는 탐색적으로 제시. 순수 인과효과 판정은 보류하며 통계 검정 통과가 분류의 정확성을 입증하지 않음 |

정책 전 지역 특성은 2022년 공통 자료로 비교한다. 주민등록인구·고령인구 비율은 12월 말, 1인 일반가구 비율은 11월 1일 기준이다. 면적은 연간, 시장은 상반기, 점포는 4분기를 목표로 한 기존 정의를 유지한다. 자료 시점·모집단을 섞지 않는다. 인구·가구 자료를 확보했으나 밀도·점포 구성 등 보류 값은 그대로 남긴다.

인구 ±몇 퍼센트, 유사도 점수·가중치, 가까운 몇 개 구 같은 새로운 선별 기준은 도입하지 않는다. 기존 후보 전체를 사용하고 규모·인구구조 차이를 공개한다. 인접성·소비 이동·마트 개폐점·지원사업의 미확인도 해소한 것으로 취급하지 않는다. 전통시장 존재나 인구 유사성이 정책 적격성을 대신하지 않는다.

명단은 매출 열람 전에 커밋·PR한다. 이후 연결 실패·관측 누락·신규 정책 근거가 발견되면 원 명단과 변경 이유를 보존한다. 매출 추세·추정치·유의성에 따라 지역을 교체하지 않는다. 자료 품질 중단 조건은 그대로 적용한다. 공통 실행기가 별도 명단을 자동으로 읽는 것은 아니므로 후속 수집 코드에서 명단 일치와 처치·비교 구분을 검사한다.

[공통 조사표](comparison-survey.md)는 명단과 자료 확인 수준을, [자료원·지표 정의](data-notes.md)와 [특성자료 수집 계획](collection-plan.md)은 취득·집계·누락 기준을 관리한다. 비교군 고정은 특성자료·공간 호환성·효과 추정 완료와 다르다.

## 4. 자료원과 수집 설계

**2026-10-21 실행 갱신:** 사전 고정한 계획대로 매출 원본을 취득했다. 구×분기×업종 95개 조합의 행 부재·공간 버전 확인 공백과 금액 환산 규칙 보완 필요로 실자료 패널 발행과 추정은 중단했다. [수집·품질 점검 기록](sales-readiness.md)을 참고한다. 아래 계획의 지역·기간·업종·방법은 변경하지 않았다. 과거 날짜의 미열람 설명은 해당 시점의 이력이다.

| 자료원 | 용도 | 현재 확인 범위 |
|---|---|---|
| 자치구 고시·공식 보도자료·의회 기록 | 정책 목록과 지역별 처치 분류 | 동대문 고시 등 일부 확인, 전체 이력은 후속 보강 |
| [추정매출-상권 OA-15572](https://data.seoul.go.kr/dataList/OA-15572/S/1/datasetView.do) | 분기·상권·업종별 결과지표 | 2026-10-21 연간 ZIP 4개 실제 취득·품질 점검, 공백으로 추정 보류 |
| [영역-상권 OA-15560](https://data.seoul.go.kr/dataList/OA-15560/S/1/datasetView.do) | 골목상권 구분과 자치구 연결 | 공간 ZIP 다운로드 및 상권 코드 고유성·자치구 연결 구조 확인 |

매출은 카드결제 자료를 보정한 추정 지표다. 제공기관은 2024년 공간 단위 개편과 2021년 이후 자료의 재제공을 안내하고 있다. 확인한 공간 파일은 2023년 작성본으로, 최신 매출 자료와 상권 경계·코드가 맞는지는 아직 확인하지 못했다. 코드가 연결되더라도 연도별로 같은 범위를 집계한 것인지 따로 확인해야 한다.

`fetch.py`에서는 원자료를 받고 열 이름·코드·분기 표기를 맞춘다. 그다음 골목상권의 4개 업종을 골라 자치구에 연결하고, 분기별 매출을 합산한 뒤 정책 목록을 붙인다. 전체 16분기 집계는 로컬에 보관하고, 2024Q1(12)만 제외한 15분기를 추정 입력 `data/panel.csv`로 만든다. 2023Q4(11)는 사전 기간에 포함하며 분기 번호를 다시 매기지 않는다. 같은 자료로 다시 실행할 수 있도록 수집 시점·원본 파일 식별 정보·해시·변환 규칙을 기록한다. 갱신 자료를 받으면 기존 입력과 구분하고 변경 내역을 남긴다.

수집 기록에는 연도별 자료 버전·상권 경계·업종 정의·비공개 또는 누락 기준도 남긴다. 선행연구에서 같은 자료를 사용했다는 사실만으로 현재 파일의 연속성을 가정하지 않는다. 수집 후에는 자치구·분기·업종별 관측 여부를 검사하고, 네 업종의 합계와 원자료 집계가 맞는지 대조한다. 해당 업종의 실제 부재와 자료 누락을 구분할 수 없으면 0으로 간주하지 않는다.

자료별 이용 조건을 실행 설정과 README에 명시한다. 원자료·가공 데이터와 인증 정보는 저장소에 포함하지 않는다. 상권을 어느 자치구에 연결할지 분명하지 않으면 임의로 연결하거나 면적 비율에 따라 나누지 않는다.

### 정책 전 특성자료 수집 기준

특성자료는 서울 25개 구 모두를 대상으로 인구 2022년 12월 말, 일반가구 2022년 11월 1일, 점포 2022Q4, 면적 2022년, 시장 2022년 상반기 파일을 사용하도록 계획한다. 서로 다른 기준일은 통일된 연말 값으로 바꾸지 않고 보존한다. 면적 기준일과 시장 파일 내부의 기준시점·유형은 취득 후 확인하며, 미확인 항목은 산출을 보류한다.

[수집·검사 계획](collection-plan.md)에 공식 출처·조회 조건·파생 지표·중복 및 공간 연결 오류 처리·완료 기준을 고정했다. 원자료 수집은 이 계획을 커밋·PR한 뒤 자료별 이용 조건 확인을 거쳐 진행한다. 최신값 대체·결측의 0 처리·특성값에 따른 자동 후보 탈락은 하지 않는다. 결과는 `data/characteristics/`에 저장하며, 매출 추정 패널이나 회귀 통제변수로 자동 편입하지 않는다. 과거 마트·SSM 및 공식 경계 자료는 확보 경로 보강이 필요해 후속 조사로 남긴다.

## 5. 구현할 작업

저장소에 있는 분석 흐름에 이 사례의 수집 코드와 검사를 연결한다. 단계별로 만들 파일은 다음과 같다.

| 단계 | 구현·운영 내용 | 산출물 |
|---|---|---|
| 계획 확인 | 스키마, 사례 ID, 사전등록 상태 및 실행 입력 확인 | `plan.yaml`, 정책 목록 |
| 수집·정규화 | 출처별 취득, 열·코드·시간축 통일, 재실행 가능한 입력 관리 | `fetch.py`, 수집 기록 |
| 패널 구축 | 상권·업종 선택, 자치구 집계, 정책 정보 결합 | `data/panel.csv` |
| 품질 검사 | 공통 자동 검사와 사례별 검사, 실패 사유 출력 | 품질 점검 기록 |
| 추정·반증 | 이벤트스터디, 가짜 시행일 검정, 판정 규칙 적용 | 추정 결과·그림 |
| 보고·재현 | 자동 보고서 생성, 해석·한계 병합, 타 참여자 재실행 | `report.md`, `discussion.md`, `run_manifest.json`, README |

수집부터 보고까지 기존 `make flow CASE=cases/YoungjaeKang-retail-hours` 흐름에 연결하는 것을 목표로 한다. 공개 고시를 읽고 같은 시기에 시행된 다른 정책을 확인한다. 기관 직접 문의·정보공개청구·회신 대기는 작업 범위에서 제외한다. 공개 자료로 확인되지 않는 사항은 미확인으로 남기고, 독립적인 수집·검사 구현은 계속 진행한다. 검토 내용은 다시 사용할 수 있는 형태로 기록한다. 고시를 자동으로 해석하거나 정기적으로 자료를 수집하는 기능까지 이번 7주 안에 만들 계획은 없다.

## 6. 자료 검사와 분석을 멈출 조건

분기는 `2021Q1=0`부터 순서대로 번호를 붙인다. 추정 입력에는 0~11, 13~15를 사용하며, 제외한 2024Q1(12)의 번호는 비워 두고 나머지 번호를 당기지 않는다. 기본 패널 열은 `gu_code`, `quarter_idx`, `treated`, `sales_krw`, `log_sales`로 구성하며 처치집단 표시 `treated`는 도입 전후에 동일하게 유지한다.

| 구분 | 검사 내용 |
|---|---|
| 공통 자동 검사 | 필수 열, 결측, 정수 시간축, 단위×시점 중복, 사전·사후 관측과 처치·비교집단 존재 |
| 사례별 추가 검사 | 업종·상권 코드 연결 누락, 자치구 대응의 유일성, 모든 구의 관측 분기 집합 일치, 제외 분기와 처치 표시 일관성 |
| 집계 검증 | 원자료와 집계 합계 대조, 0과 누락의 구분, 로그 변환 가능 여부, 필요한 업종·상권 구성의 누락 |
| 근거 검토 | 공간 버전, 정책 이력, 지원사업·후속 정책의 확인 수준과 해석 제한 |

중복·연결 실패·해결되지 않은 결과 결측 등 입력 오류가 있으면 실자료 추정을 중단하고 검사 결과를 남긴다. 정책 이력이나 공간 버전이 미확인인 경우에는 계산이 가능하더라도 인과효과 판정을 보류한다.

실자료 분석이 중단되면 동일한 열 구조의 시뮬레이션으로 정상 실행과 오류 시 중단 여부를 확인한다. 실제 자료와 시뮬레이션은 자료·설정·결과를 따로 저장하고 보고서에서도 구분한다.

## 7. 분석 방법과 판단 기준

자치구와 분기 고정효과를 포함한 이벤트스터디를 사용한다. 분석상 시작점은 2024Q2(`treat_time=13`), 기준 분기는 2023Q3(`ref_period=-3`), 상대시점 범위는 `[-13, 2]`로 설정한다. 추가 통제변수는 넣지 않는다. 주 추정량은 전환 후 3분기 계수의 단순평균이다. 제외 분기의 빈 상대시점(-1)은 추정에서 제거한다. 2023Q4를 포함하되 기준 분기는 기존 2023Q3(-3)을 유지한다. 12월 말 행정예고가 있는 2023Q4(-2)를 별도 사전 계수로 살펴보기 위해서다. 이 분기를 포함한다고 선반영 가능성이 없다고 가정하는 것은 아니며, 사전추세 점검과 해석에 반영한다.

2023Q4에는 코리아세일페스타에 맞춰 동대문구 휴업일을 11월 12일에서 5일로 한 번 옮긴 이력도 있다(두 날짜 모두 일요일). 따라서 해당 사전 계수를 12월 행정예고의 선반영만으로 해석하지 않는다. 이 한시 변경은 [서울시 안내](policy-verification.md#서울시-7개-구-한시-변경-안내)에 따르면 종로·중랑·마포·강서·영등포·서초에도 적용됐으므로 동대문만의 사건으로 취급하지 않는다. 2024Q3의 추석 한시 변경도 함께 기록한다. [고시별 확인 범위](policy-verification.md#동대문구-한시-변경)를 참고하며, 이들 사건으로 기준 분기나 제외 분기를 임의로 바꾸지 않는다.

| 항목 | 초기 기준 |
|---|---|
| 불확실성 | 양측 유의수준 0.05, 자치구 단위 추론 |
| 소수 처치 | 공통 구현의 무작위화 추론 사용 조건 확인, 단일 처치의 한계로 최상 판정도 조건부 |
| 사전추세 | 결합검정 유의수준 0.10, 기각 시 판단 불가 |
| 가짜 시행일 | 2023Q1, `shift=5`; 2021Q1~2023Q4만 사용, 유의수준 0.10 |
| 기간 기준 | 사전 최소 8분기, 사후 최소 3분기. 미달 시 초기 효과 해석 보류 |
| 군집 수 | 20개 미만이면 조건부로 판정하고 검정력 한계 기록 |
| 신뢰구간 | 0을 포함하면 불확실로 해석, 효과가 없다고 단정하지 않음 |

가짜 시행일 검정은 공통 코드의 DID를 사용한다. 추정 패널에서 `quarter_idx < 13`인 0~11만 전달되므로 가짜 사전은 0~7(2021Q1~2022Q4), 가짜 사후는 8~11(2023Q1~Q4)이다. 실제 전환기인 2024Q1은 입력 패널에서 빠져 이 검정에도 포함되지 않는다. 이벤트스터디의 기준 분기 설정은 이 DID 검정에 적용되지 않는다.

위 기준으로 첫 분석을 진행한다. `plan.yaml`이 지원하는 조건은 `abstention`과 `thresholds`에 반영하고, YAML에서 자동으로 검사할 수 없는 사후 기간과 근거 확인 여부는 별도 검사와 해석 기록에 남긴다. 가짜 시행일 검정에서 유의한 결과가 나오면 조건부로 낮춘다. 시차 도입을 단순 동시 도입 모형에 혼합하면 판단 불가로 처리한다.

무작위화 추론을 여러 번 반복해도 정책을 바꾼 지역이 하나라는 한계는 남는다. 사전추세 검정을 통과하더라도 두 집단이 정책 없이 같은 추세를 보였을지, 어느 구든 동대문구 대신 정책을 도입할 수 있었을지는 별도의 가정이다. 인접 지역을 빼고 결과가 달라지는지 살펴보는 분석은 추후 추가한다. 추가할 때는 경계 자료와 제외 목록을 사전에 정한다. 현재 공통 파이프라인에서 자동 실행되지 않는 검사는 사례별로 구현·검증한 뒤 포함한다.

## 8. 제출 순서와 남은 일

초기 계획은 [PR #9](https://github.com/CausalInferenceLab/policy-effect-analytics-agent/pull/9)로 2026-10-12(한국시간) main에 병합됐다. 2026-10-12 보완은 매출 원자료 열람 전 선행연구 검토와 분기 처리 합의를 반영했다. 기여 방향·지표 해석·근거 확인 절차를 구체화하고, 기존에 제외했던 2023Q4를 사전 기간에 포함한다. 2024Q1은 추정에서만 제외해 전환기 자료도 보관한다. 전체 자료 범위, 지역 후보, 네 업종, 추정 방법, 기준 분기와 판정 기준은 유지한다. 변경은 결과를 확인하기 전에 결정했다.

이번 2026-10-20 보완은 공개 정책 근거와 한계를 보강하고 점포 예외 전수 확인 조건을 변경해 비교군 20개 구를 고정한다. 매출 열람 전 결정이며 후속 수집과 구분한다.

2026-10-20 [PR #29](https://github.com/CausalInferenceLab/policy-effect-analytics-agent/pull/29)를 제출했다. 정책 원문을 보강하고 처치 1개·비교 20개·제외 3개·보류 1개를 명단과 계획에 반영했다. 기존 20개 후보 전체를 사용하며 최초 5개 구는 조사 순서였고 최종 선정 명단이 아니었다. 매출 원자료는 아직 열람하지 않았다.

#29는 최신 main에서 이번 계획 변경만 분리했으며 최초 제출 커밋(`4cd1449`)의 로컬 검사와 원격 CI가 통과했다. 후속 커밋의 CI 상태는 PR에서 확인한다. 특성자료 구현 [PR #22](https://github.com/CausalInferenceLab/policy-effect-analytics-agent/pull/22)와 #29는 모두 리뷰·병합 대기 중이다. 같은 문서를 수정하므로 병합 순서에 따라 충돌을 정리한다. #22의 코드가 이번 계획 PR에 포함된 것은 아니다.

남은 신규 PR은 아래 두 단계다. 수집·품질 검사·추정은 별도 PR 세 개가 아니라 수집·분석 PR 내부의 실행 순서다.

| PR | 주요 작업 | 완료 기준 |
|---|---|---|
| 수집·분석 | 자료 버전·이용 조건 확인 → 실제 다운로드 → 21개 구 패널 구성 → 품질 검사 → 계획대로 추정·반증 | fetch.py와 make flow로 재현, 검사 결과와 해석 제한 기록. 입력 기준 미충족 시 중단 사유 기록 |
| 리포트 | 결과·그림 정리, discussion.md 작성, 보고서 재생성, 재현 안내·타 참여자 확인 | 산출물과 보고서 일치, 정책 오분류·동시 정책·공간 파급·소수 처치 한계 명시 |

수집·분석 PR에서 진행할 세부 순서는 아래와 같다.

1. 고정한 명단을 수집 코드에 적용한다. 전체 집계는 21개 구×16분기 336행, 추정 입력은 2024Q1을 제외한 315행인지 검사하고 분기 번호를 보존한다. 이는 예정된 검사 기준이며 아직 생성한 패널이 아니다. 예외 이력은 후속 보강하며 수집의 선행 조건으로 두지 않는다.
2. 동대문 연계 지원사업의 실제 집행일과 대상지를 확인한다. 분리가 어려우면 요일 변경만의 효과라는 해석을 보류한다.
3. 제공 문서에서 매출·공간 버전, 업종 정의와 제공 기간을 확인한다. 계획 변경이 필요하면 매출 원자료를 열기 전에 반영해 커밋·PR한다.
4. 수집 단계에서 실제 다운로드, 코드 연결, 업종별 누락과 집계 가능성을 검사한다. 제공 페이지 확인과 파일 취득·품질 검증 완료를 구분한다.

프로젝트 범위와 일정은 `plan.md`에, 실행 설정과 사전등록 기준은 `plan.yaml`에 기록한다.

[참여 가이드](../../docs/ops/mentee-guide.md)에 따른 케이스 제안 이슈의 등록·연결 여부는 추가 확인한다. 정책 목록과 시행 시점·대상·측정 항목의 확인 결과는 정책 확인표에 기록한다. 초기 실행의 비교 후보 목록·확인 수준·자료 처리 가정·판정 규칙을 [계획 작성 가이드](../../docs/strategy/plan-guide.md)와 [스키마](../../core/schema/plan.py)에 맞춰 YAML에 반영하고, 매출 결과 자료를 열기 전에 커밋·PR한다. 미확인 정책 날짜를 임의 값으로 채우지 않는다.

계획 PR → 수집·분석 PR → 리포트 PR 순서로 단계별 제출한다. 관련 검사와 `make check` 결과를 기록하고, 실행하지 못한 검사는 이유를 명시한다. 리뷰 1명 승인과 CI 통과 후 squash merge 절차를 따른다. 공통 모듈 변경이 필요하면 먼저 이슈로 논의한다.

결과 확인 후 기간·지역·업종·방법을 바꾸면 변경 이유와 영향을 커밋 기록 및 `discussion.md`에 남긴다. 결과를 본 뒤 바꾼 계획을 처음부터 정해 둔 것처럼 설명하지 않는다.

| 남은 일 | 지금 기록할 내용 | 확인 후 할 일 |
|---|---|---|
| 지원사업 집행일·대상지 | 함께 진행한 사업과 아직 모르는 내용 | 정책 효과 범위와 기간 재검토 |
| 비교구 전체 이력·점포 예외 | 고정한 20개 구와 확인 공백·정책 오분류 가능성 | 새 근거가 나오면 계획 변경 이력을 남기며 해석 보완 |
| 공간 경계·코드 버전 호환성 | 코드 연결 결과와 자료 비교의 한계 | 연도별 자료를 같은 기준으로 연결 |
| 추가 기간·업종·분석 방법 | 첫 분석과 구분해 기록 | 별도 계획을 세워 추가 분석 |

7주 안에 확인하지 못한 근거는 과정이 끝난 뒤에도 계속 찾아본다. 근거가 부족한 분석은 판단 불가로 보고한다. 본 프로젝트는 학습·연구용 오픈소스 분석이며 정부·공공기관의 공식 평가가 아니다.

## 2026-10-21 수집·분석 로컬 작업 마무리
