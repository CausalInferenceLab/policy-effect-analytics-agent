## 품질 점검 결과와 중단 이유

검사 대상 매출은 골목상권(`A`)·계획한 4업종이다. 선택 행의 분기 범위·중복 키·금액 결측/비정상값·영역 연결을 점검했다. 선택 매출 상권의 영역 코드 미연결은 0개였다. 명단에 포함된 21개 구의 선택 행은 7,213개이며 명시적 매출 0행은 없었다.

21개 구 × 16분기 × 4업종 = **1,344개 조합 중 95개 조합에 관측 매출 행이 없다.** 2024Q1을 제외한 추정 기간에도 1,260개 조합 중 87개가 비어 있다. 이는 매출이 0이라는 뜻이 아니며, 실제 업종 부재·비공개·자료 누락 중 무엇인지 확인하지 못했다.

| 구 | 업종 | 매출 행이 없는 분기 수 |
|---|---|---:|
| 강남 | 수산물 | 16 |
| 노원 | 수산물 | 11 |
| 마포 | 수산물 | 16 |
| 송파 | 수산물 | 10 |
| 용산 | 수산물 | 14 |
| 종로 | 수산물 / 청과 / 반찬 | 16 / 8 / 4 |

동대문의 구×분기×업종 조합에는 행이 존재하지만, 모든 개별 상권의 값이 관측됐다는 뜻은 아니다. 진단용 영역 파일의 21개 구 골목상권 934개 × 16분기 × 4업종 격자에서 행 부재 조합은 52,563개다. **이 격자는 실제 영업 조합의 모집단이 아니므로 이를 결측률로 해석하지 않는다.** 각 상권에 네 업종이 모두 영업한다고 가정하지 않는다.

현재 중단 조건은 다음과 같다.

1. 구×분기×업종 공백과 개별 상권 행 부재를 해석할 근거가 부족하다. 누락을 0으로 채우거나 관측 행만 더해 완전한 합계로 취급하지 않는다.
2. 2023 영역 ZIP과 재제공 매출의 기간별 경계·버전 호환성이 미확인이다.
3. 추가 대조에서 월평균 해석의 공식 근거를 확보했다(아래 후속 작업 참조). 전 기간의 적용 범위와 분기 총액 환산 규칙을 문서화하기 전에는 변환하지 않는다.

비교군·업종·기간·추정 설정은 변경하지 않았다. 결과 확인 후 임의로 결측이 적은 구나 업종을 고르지 않았다. `plan.yaml`의 제공 상태 설명은 사전등록 당시 기록이며 최신 취득·점검 상태는 이 문서와 원본 수집 기록으로 구분한다.

```bash

.venv/bin/python cases/YoungjaeKang-retail-hours/fetch.py build \
  --snapshot cases/YoungjaeKang-retail-hours/data/raw/sales/20261021T120614Z

# 합성 자료로만 패널·분석·반증·보고서 실행 확인

  cases/YoungjaeKang-retail-hours/fetch.py simulate

.venv/bin/python -m pytest -q cases/YoungjaeKang-retail-hours/test_*.py
make check PY=.venv/bin/python
```

`build` 결과는 `data/sales-audit/<snapshot 이름>/quality.json`, `coverage.csv`, `absent-combinations.csv`에 저장한다. coverage의 0은 **관측 행 수가 0**임을 뜻하며 매출 0을 뜻하지 않는다. `quality.json`에 원본·계획·명단·변환 코드 해시와 중단 사유를 기록한다. 현재 `fetch.py`는 진단 단계 구현이며, 확인 공백 해소 전 실자료 패널 발행 기능은 제공하지 않는다.

합성 실행은 고정 seed 20261021과 가상 지역 21개를 사용하며 `data/simulation/` 아래 매번 새 폴더에 설정·336행 전체 패널·315행 추정 패널·분석 산출물을 저장한다. 설정은 `synthetic_data: true`, 자료 이용 조건은 `synthetic`이다. 사전등록 우회 옵션은 이 합성 실행에만 적용한다. 합성 결과는 실제 정책 효과가 아니다.

공통 자동 검사는 필수 열·시간 정수형·결측률·처치/비교 단위·중복 등을 확인한다. 사례별 검사는 원본 해시, 연간 4분기, 골목상권·4업종, 상권 키 중복, 금액 이상, 명단 1/20/3/1, 관측 조합, 2024Q1 제외 후 번호 보존과 336/315행 구조를 추가로 확인한다. 공통 실행기는 기존 `data/panel.csv`가 있으면 수집 검사를 건너뛰므로 출처가 다른 기존 패널을 이 사례 폴더에 넣지 않는다.

다음 단계는 공개 문서에서 금액의 기간 정의·행 생략 규칙·공간 적용 버전을 확인하는 것이다. 확인이 불가능한 경우 계획 변경 여부를 별도 논의하고, 이미 원자료를 열었다는 사실과 변경 이유를 기록해야 한다. 지금 상태에서 원래 계획의 효과 추정 완료를 주장하지 않는다.

### 금액의 기간 정의: 월평균 해석 근거 확보

서울시·서울디자인재단의 [2026-02-09 보도자료 「DDP 관람객 10명 중 7명, 인근 동대문 상권에서 지갑 열었다」](https://culture.seoul.go.kr/culture/cmmn/file/fileDown.do?atchFileId=af365d87d23c4c5b8411d3ba236292f6&bbsId=&fileSn=2&menuNo=200050) 8쪽은 상권분석서비스의 분기별 당월 매출액을 **분기 월평균**으로 설명하고 연간 환산에 3개월을 곱한다.

이 문서의 2024년 동대문패션타운 관광특구 수치를 우리가 받은 OA-15572 CSV의 동일 상권·전체 제공 업종 합계와 대조했다. 네 분기가 모두 문서의 표시 정밀도(억원 소수 첫째 자리)에서 일치했다. 이 대조는 **금액 정의를 검토하기 위한 별도 상권의 재현 점검**이며 동대문구의 정책 효과 분석이 아니다.

| 분기 | 보도자료(억원, 월평균) | 원본 합계(억원) |
|---|---:|---:|
| 2024Q1 | 1,144.5 | 1,144.53152227 |
| 2024Q2 | 1,279.9 | 1,279.89321952 |
| 2024Q3 | 1,139.6 | 1,139.55443974 |

보도자료 본문에는 자료명을 ‘점포–상권’으로 적은 부분이 있으나, 표 제목은 추정매출이며 실제 매출 ZIP 수치와 네 분기 모두 맞는다. 따라서 현재 CSV의 `당월_매출_금액`을 무조건 분기 총액으로 읽으면 안 된다는 근거가 확보됐다. 직접 숫자를 대조한 범위는 **2024년 한 관광특구**이고 2021~2023 모든 업종의 정의·버전까지 전수 확인한 것은 아니다.

후속 적용안은 월평균 원본 열을 보존하고, 같은 기간 정의의 적용 범위를 확인한 뒤 분기 총액을 3배로 환산하는 것이다. 현재 실자료에 환산을 적용하지 않았고 `plan.yaml`도 바꾸지 않았다. 모든 관측치에 동일하게 3을 곱하면 로그에 상수 `log(3)`만 더해지므로 고정효과 모형의 처치 계수는 변하지 않지만, 금액 수준·단위와 보고는 달라진다. 이 수학적 성질이 누락이나 공간 기준 문제를 해결하는 것은 아니다.

[2020년 공개 문의 답변](https://data.seoul.go.kr/together/notice/inquireView.do?bbsCd=10003&seq=7aa4c738a4ea9b19b487fa661cddf994&ditcCd=QNA01)은 원천부서에서 분기별로 자료를 받아 제공한다고 설명한다. 이는 **제공 주기**에 관한 답변으로, 분기 총액이라는 증거로 사용하지 않았다.

### 관측 행 부재: 기존 점포 원본과 비교

새 데이터셋으로 분석 지표를 바꾸지 않고, 이미 취득해 검증한 2022년 점포 ZIP의 2022Q4와 매출 2022Q4를 같은 상권·업종 코드로 외부결합했다. 두 원본의 해시를 재확인했다. 21개 구에서 어느 쪽에든 관측된 2,381개 조합은 다음과 같다.

| 점포·매출 관측 상태 | 조합 수 |
|---|---:|
| 점포 수 양수, 매출 행 없음 | 1,900 |
| 점포 수 양수, 매출 행 있음 | 456 |
| 점포 수 명시적 0, 매출 행 없음 | 25 |

동대문에도 점포 수 양수·매출 행 부재 조합이 101개 있다. 따라서 앞선 ‘동대문의 구×분기×업종 공백 0개’는 개별 상권 매출의 완전성을 뜻하지 않는다. 점포자료에는 당기 폐업 점포도 포함되고 두 자료의 공간·표본 정의가 동일하다는 확인도 남아 있으므로, 1,900개 전부를 매출 데이터 오류나 결측으로 단정하지 않는다. 다만 **매출 행이 없으면 점포가 없으니 매출 0이라는 일괄 처리는 뒷받침되지 않는다.**

이 점검은 2022Q4의 두 공개 파일 사이의 관측 차이를 보여준다. 2021~2024 전체의 누락 규칙이나 누락 매출액을 추정한 것이 아니며, 점포 수로 매출을 보간하지 않았다.

```bash
.venv/bin/python cases/YoungjaeKang-retail-hours/sales_crosscheck.py \
  --sales-snapshot cases/YoungjaeKang-retail-hours/data/raw/sales/20261021T120614Z \
  --characteristics-snapshot cases/YoungjaeKang-retail-hours/data/raw/characteristics/20261013T125722Z-8lppdh9s \
  --output cases/YoungjaeKang-retail-hours/data/sales-audit/crosscheck-20261021
```

출력은 `crosscheck.json`, `store-sales-pairs-2022Q4.csv`, `store-sales-summary-2022Q4.csv`이며 Git 제외 대상이다. JSON에 입력 원본과 코드 해시, 공식 문서 URL·쪽수·대조 결과를 기록한다. 이 검사는 실자료 패널 발행을 자동 승인하지 않는다.

### 아직 해결되지 않은 것

공개 문의 목록에서 ‘추정매출’ 9건, ‘상권’ 69건, ‘월평균’ 1건을 확인하고 관련 공개 답변을 읽었다. 비밀글 본문에는 접근하지 않았고 기관 문의도 보내지 않았다. 검토한 공개 답변과 제공 문서에서는 현재 ZIP의 행 생략 규칙이나 2023 영역 ZIP의 재제공 매출 적용 범위를 확정할 근거를 얻지 못했다. 최신 미확인 사항은 **행 생략 규칙·공간 호환성**, 그리고 확보한 월평균 근거를 전 기간에 적용할 범위와 환산 규칙의 문서화다. 금액 정의는 종전의 ‘근거 없음’에서 ‘공식 설명과 2024년 수치 대조 확보’로 진전됐다.

## 이번 변경의 마무리 범위와 분석 재개 조건

이번 수집·분석 단계의 로컬 산출물은 **원본 취득·품질 진단·근거 대조·합성 실행 검증 및 실자료 중단 기록**이다. 원래 계획의 실자료 패널·추정·반증은 완료되지 않았다. 근거가 부족하면 멈춘 이유와 합성 검증 범위를 남긴다는 `plan.md`의 완료 기준을 적용했다. 효과가 없다는 결론도 내리지 않는다.

감사 결과에는 전환기 제외 후 공백 수도 별도로 저장한다. 기존 `data/panel.csv`가 발견되면 경고 사유를 기록하고 덮어쓰거나 삭제하지 않는다. **이 검사가 공통 `make flow` 자체의 기존 패널 재사용을 막지는 않는다.** 현재 실자료에는 `fetch.py build`까지만 사용하며, 임의 패널을 넣고 공통 실행기를 호출하지 않는다.

## 후속 실자료 진단: 재다운로드·고정 관측 표본 대안 검토

앞 절의 ‘로컬 마무리’는 구현과 중단 기록 범위이며 분석 준비 완료를 뜻하지 않는다. 사용자 요청에 따라 원래 분석을 재개할 수 있는지 추가로 확인했다.

### API와 ZIP의 일치 범위

[공식 API 명세](https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-15572&srvType=A)의 공개 sample 키로 `VwsmTrdarSelngQq/1/5/<년분기>`를 2021Q1~2024Q4에 조회했다. 각 분기의 API 전체 행 수가 연간 ZIP의 해당 분기 행 수와 모두 같았다. 분기별 첫5행, 총80행의 상권·업종 키 및 매출 금액도 ZIP과 일치했다. 무작위 표본이나 전체행 대조는 아니며, 행 수·80행 일치만으로 모든 값과 공간 버전의 동일성을 증명하지 않는다. 다만 API로 교체하면 현재 공백이 해소된다고 볼 근거는 얻지 못했다. 원본 응답·조회 URL·해시는 로컬에 보존했다.

추가로 [공식 제공정보 PDF](https://golmok.seoul.go.kr/images/seoul_info.pdf) 1~3쪽과 공개 문의6건을 확인했다. PDF는 분기 제공, 점포수에 당기 폐업 포함, 카드매출 보정 방식을 설명하지만 행 생략 기준과 과거 영역의 적용 기간은 명시하지 않는다. 오래된 상권·배후지 정의나 구 상권 폐기 답변을 현재 자료의 경계 호환성 근거로 사용하지 않았다.

### 관측 집합의 변화

`fetch.py build`는 `observation-diagnostics.csv`도 생성한다. 고정21구×16분기×4업종의 각 조합에 관측 상권 수, 관측 행의 원본 금액 합, 직전 분기 대비 관측 진입·이탈 수, 16분기 모두 관측된 상권 수를 기록한다. 행이 없는 조합의 금액은 빈칸이며0으로 대체하지 않는다. 첫 분기는 직전 분기가 없어 진입·이탈을 빈칸으로 둔다. 금액은 기간 환산 전 원본값이며 완전한 골목상권 매출 합계가 아니다. 관측 진입·이탈은 개업·폐업을 뜻하지 않는다.

- 전체21구의 관측 상권·업종 조합 수는 2021Q1 462개에서 2024Q4 431개로 바뀐다. 서로 다른 업종을 따로 세므로 고유 상권 수와 다르다.
- 동대문은 분기마다24~31개 조합이며, 2024Q1/2/3/4는 각각27/26/24/26개다. 구×분기×업종 행이 모두 있다는 사실만으로 동일 표본이라고 할 수 없다.
- 16분기 모두 관측된 조합은 전체312개(육류152·수산19·청과66·반찬75), 동대문19개(11·1·2·5)다.
- 완전 관측 조합으로 제한하면 종로는 네 업종 모두0개가 된다. 이 방법은 고정21구 계획을 그대로 유지하는 해결책이 아니며, 사후기간 관측 여부로 표본을 골라 생존·선택 편향도 생긴다. 추정용 표본 선택에 적용하지 않았다.

### 실행 가능한 범위와 대안의 판단

| 방법 | 현재 판단 | 필요한 변경 |
|---|---|---|
| 원래 계획의 전체 골목상권 매출 효과 | 현재 공개 근거로 추정 불가 | 행 생략·집계 가능성과 공간 적용 근거 확보 |
| 관측된 행만의 금액·관측 집합 기술통계 | 실행 완료 | 전체매출이나 정책효과로 해석하지 않음 |
| 관측 행 합계로 탐색 이벤트스터디 | 별도 지표로 계산은 가능하나 미실행 | 관측 범위 변화가 섞인 지표임을 인정하는 사후 계획 보완 필요 |
| 16분기 완전 관측 표본 | 원래 계획의 대안으로 채택하지 않음 | 종로 탈락 및 사후 생존자 선택 문제 발생 |
| 자치구 전체 매출 자료로 대체 | 미채택 | 골목상권 한정이라는 연구대상이 바뀌므로 별도 계획 필요 |

현재 자료는 관측되지 않은 매출의 크기·변화를 알려주지 않는다. 따라서 관측 합계의 증감만으로 전체매출 효과를 정할 수 없고, 모든 값에3을 곱해도 이 문제는 해결되지 않는다. 기존 계획을 유지하면서 가능한 실자료 기술통계를 실행했으며, 탐색 지표로의 변경을 기존 계획의 자동 연장으로 취급하지 않는다.

후속 검사: 관측 진입·이탈과 금액 미관측 보존 회귀1개를 추가해 사례69개. 기존 합성 실행과 달리 위 진단 수치는 실제 원본에서 계산했으며 정책 효과 추정값은 없다.
