**판정은 조건부 가능이며 진행을 추천한다.** 2024년 강남대로 버스 운행 조정 전후의 일반도로 속도 변화를 분석하고, 같은 정제 자료로 다음 1시간과 3시간의 속도를 예측하는 모델을 학습한다. 권장 구성은 비교 전후 분석과 DiD, CatBoost CPU 기준모델, 작은 PatchTST GPU 모델이다. 기존에 알려준 RTX 5070 Ti 16GB를 기준으로 작은 신경망 학습을 계획할 수 있다. 학습 속도와 최대 batch는 실제 환경에서 확인한다.

계획은 15작업일, 하루 3\~4시간의 약 45\~60시간을 가정한다. 기관 회신 대기시간은 별도다. 10작업일에는 데이터 구축·정책 비교·CPU 모델까지 완성하고, 나머지 기간에 GPU 실험을 진행한다. 인과 해석이 어려우면 관측된 변화와 한계를 보고하며 예측 실험은 독립적으로 완주한다.

검토 기준일은 **2026-10-28**이다. 첨부한 plan.md, README(1).md, research-request.md와 저장소 기준 커밋 46a824e535865f228c78d25b92ddcfa2773de68b를 검토했다. 이번 검토에는 실제 TOPIS 파일의 헤더·링크 메타데이터 확인을 포함한다. 정책 효과 계산과 속도값 요약, 모델 학습은 포함하지 않는다.

## 주 지표

주 지표는 **고정 링크의 길이가중 속도지수**를 권한다. 동일 링크와 고정 길이 가중치를 유지하고, 17\~20시의 세 시간 구간을 동일 비중으로 평균한다. 단위 확인 후 km/h로 통일한다.

```math
Y_{c,d}=\frac{1}{3}\sum_{h\in H}\sum_{\ell\in c}w_\ell v_{\ell,d,h},
\qquad w_\ell=\frac{L_\ell}{\sum_{j\in c}L_j}
```

이는 고정 도로구간의 속도지수이며 실제 차량의 완주시간이나 모든 일반 차량의 모집단 평균은 아니다. 주 분석에서는 세 링크×세 시간의 9개 값이 모두 유효한 날만 지수를 계산한다. 도로별·전후별 가용률을 함께 공개한다. 결측 때문에 매일 링크 구성을 바꾸거나 가중치를 재정규화하지 않는다. 가용률이 낮거나 전후 차이가 크면 계획을 수정해 기록하고 인과 해석을 낮춘다.

통행시간은 연결성과 단위를 확인한 경우에만 보조지표로 검토한다. 링크별 거리/속도를 합산해야 하며 산술 평균속도로 전체 경로 통행시간을 만들지 않는다.

## 비교 도로

조사 후보는 동작대로 사당역\~이수역, 송파대로 석촌역\~가락시장역, 시흥대로의 유사한 간선 구간이다. 모두 **비처치 미확인 후보**다. 직접 연결 도로에 비해 우회 오염이 작을 가능성이 있지만 통근수요·토지이용·여름 수요 변화가 강남과 다를 수 있다.

선정 순서는 노선과 우회 노출 → 공사·차로·정류장 변경 → 고정 링크 가용성 → 정책 이전 속도 패턴이다. 사전 자료에서 수준·요일별 형태·변동성을 비교하고, 선정 규칙을 먼저 기록한다. 사후 효과가 잘 나오는 비교군으로 바꾸지 않는다. 반대 방향과 사평대로·서초대로 등 연결로는 영향 구간 후보로 먼저 분류한다.

## 추정과 불확실성

주 방법은 도로축과 날짜 고정효과를 둔 DiD이며, 주별 이벤트 스터디는 사전 차이와 변화 양상을 보는 진단으로 사용한다. 날짜 고정효과와 서울 공통 날씨변수는 중복될 수 있으므로 단순히 모두 넣지 않는다. 날씨는 우천 민감도와 지역별 차이 점검 등에 사용한다.

처치 도로는 하나다. 링크 수나 시간 수를 독립적인 정책 표본 수로 세지 않는다. 비교 도로가 적을 때 순열을999회 반복해도 독립적인 도로 수는 늘지 않는다. 사전 추세 검정 비유의성도 평행추세를 증명하지 않는다. [Roth 2022](https://www.aeaweb.org/articles?id=10.1257/aeri.20210236)

효과 추정치, 사전 추세, 비교군·기간 민감도를 우선 제시한다. 시간 의존성을 다루는 추가 구간 추정은 같은 날짜 블록을 모든 도로에 함께 적용하고 처치 시점·설계를 보존하는 방식으로 별도 검토한다. 주 단위 블록도 전후6주에서는 불안정할 수 있다. 이 구간은 선택한 모형과 비교군에 조건부이며 동시 정책이나 우회 오염 편향을 포함하지 않는다.

합성통제·SDID는 충분한 비교 후보와 사전 기간이 확보될 때 후속 과제로 둔다. 한 처치 단위에서도 추론 가정은 필요하다. [Abadie 2021](https://www.aeaweb.org/articles?id=10.1257/jel.20191450), [SDID 공식 추론 문서](https://synth-inference.github.io/synthdid/reference/vcov.synthdid_estimate.html)

# 6 모델 학습 계획

## 모델 선택

| 우선순위 | 모델 | 역할 |
| - | - | - |
| 필수 | 마지막 관측값·지난주 같은 시각·학습기간 요일시간 평균 | 단순 기준선 |
| 필수 | CatBoost CPU | 시간 lag·도로 ID·달력 특성의 지도학습 기준모델 |
| 권장 GPU | 작은 PatchTST | 시간 패턴을 학습하는 Transformer 비교 |
| 일정 축소 | DLinear | 작은 신경망 학습으로 범위를 줄일 때 |
| 선택 확장 | Chronos-2 zero-shot | 사전학습 시계열 모델의 추가 비교 |
| 후속 연구 | DCRNN·STGCN | 당시 도로 연결 그래프가 확보되면 확장 |

[CatBoost 공식 논문](https://proceedings.neurips.cc/paper/2018/hash/14491b756b3a51daac41c24863285549-Abstract.html)은 범주형 특성을 포함한 boosting을 설명한다. [PatchTST](https://arxiv.org/abs/2211.14730)는 시계열을 패치로 나누고 채널 간 모델 가중치를 공유한다. 기본 PatchTST는 도로 연결을 명시적으로 다루는 그래프 모델이 아니다.

서울 TOPIS 시간별 속도로 CatBoost 등을 학습해 다음 시간 속도를 예측한 직접 사례가 있다. [Nesa와 Yoon 2024의 Dataset description 및 Speed prediction models](https://www.nature.com/articles/s41598-024-74545-8)를 설계 참고자료로 삼되, 정규화·평가 분할을 그대로 복제하지 않는다. SHAP 변수 중요도는 정책의 인과효과와 구분한다.

## 데이터와 시간 분할

정책 분석용 세 링크에만 학습을 한정하지 않고, 동일 의미로 관측되는 20\~100개 링크의 24시간 자료로 시작한다. 퇴근시간만 잘라 연속 시계열을 끊지 않는다.

| 분할 | 제안 기간 |
| - | - |
| 학습 | 2023-01-01\~2024-03-31 |
| 검증 | 2024-04-01\~04-30 |
| 최종 사전 평가 | 2024-05-01\~06-16 |
| 별도 정책 후 평가 | 2024년 7\~8월의 사전에 정한 구간 |

사전 평가 기간에도 5월의 다른 변화가 있을 수 있다. 여기서는 시간순 예측 성능을 평가하며, 그 기간이 모든 정책에서 자유롭다고 가정하지 않는다. 2023년 자료가 어렵다면 2024년 상반기로 줄이고 계절 일반화의 한계를 기록한다.

입력 후보는 과거1·2·3·24·168시간 속도, 과거로만 만든 이동평균, 시간·요일·공휴일, 도로 ID다. 예측 시점 이후 실제 날씨와 다른 도로의 미래 속도는 넣지 않는다. 모든 링크에 동일한 날짜 경계를 적용하고, scaler·결측 처리·특징 선택은 학습 데이터에서만 맞춘다. 평가 label이 학습 경계를 넘어가지 않도록 window를 만든다.

## 작은 PatchTST 시작 설정

입력168시간, 출력3시간, encoder2층, hidden64, head4, patch12, stride6, batch16을 출발점으로 제안한다. 논문의 최적 설정이나 이 GPU에서 검증된 성능값은 아니다. 100학습 step으로 실제 forward·backward·optimizer step·동기화를 확인하고 peak VRAM과 step 시간을 기록한다. 후보 설정1\~2개를 검증 구간에서 고른 뒤 선택 모델을 seed3개로 반복한다.

RTX5070 Ti는 Blackwell 계열이다. [PyTorch2.7 공식 발표](https://pytorch.org/blog/pytorch-2-7/)는 Blackwell·CUDA12.8 지원을 안내했다. 실행 시점의 공식 stable 설치 안내를 따르고 실제 학습으로 호환성을 확인한다. 특정 옛 버전을 무조건 고정하지 않는다.

## 평가와 해석

MAE를 주 지표로 사용하고 단위 확인 후 km/h로 보고한다. 1시간 ahead를 주 평가로 정하고,3시간·퇴근시간·도로별 MAE와 RMSE를 보조로 둔다. 속도0 근처에서 불안정한 MAPE는 주 지표로 사용하지 않는다. 모델마다 학습시간·peak VRAM·파라미터 수를 함께 기록한다. 복잡한 모델이 기준선보다 좋지 않아도 재현 가능한 비교는 완료된 결과다.

**정책 후 실제 속도 lag를 입력한 예측은 실시간 예측 실험이다. 그 lag에 정책 영향이 포함되므로 예측값을 정책이 없었을 반사실로 해석하지 않는다.** 반사실 추정을 하려면 정책에 영향을 받지 않는 입력과 별도의 식별 설계가 필요하다.

[Chronos-2 공식 카드](https://huggingface.co/amazon/chronos-2)는120M 파라미터, Apache2.0, 단변량·다변량·공변량 입력과 CPU/GPU 추론을 명시한다. 여유가 있을 때 zero-shot 비교 한 가지를 추가한다. 사전학습에 사용된 데이터와 평가셋 중복도 확인한다.

# 8 저장소와 에이전트 작업 구성

기준 커밋의 CONTRIBUTING.md, docs/tracks/analysis.md, docs/strategy/plan-guide.md와 core/schema/plan.py, core/estimators/did.py, ri.py를 확인했다.

저장소의 실행 계획은 did·event_study·its를 허용하며 정의되지 않은 필드를 거부한다. ML 설정을 plan.yaml에 임의로 추가하지 않는다. 실제 코드에서 소수 처치 단위와 균형패널 등 조건이 맞으면 순열 추론으로 전환하는 경로를 확인했다. 그 기능이 도로들의 교환 가능성이나 정책 비노출을 입증하지는 않는다.

| 파일·산출물 | 역할 |
| - | - |
| plan.md | 확정 근거, 제안, 미확인 사항과 변경 이유 |
| plan.yaml | 공통 엔진의 정책 분석 설정 |
| ml_plan.md 또는 별도 ml_config.yaml | 예측 대상, 시간 분할, 모델, 평가 규칙 |
| fetch.py | 출처·파일 구조·해시를 기록하는 수집 |
| links 관련 설정 | 포함 링크, 방향, 역할, 출처, 확인 상태 |
| 수집 기록과 품질 보고 | 누락·중복·시간·ID 연속성·전후 가용률 |

| ML 평가 보고 | 동일 평가표, 환경, 비용, 재현 명령 |

실제 plan.yaml에서 일별 도로축 분석을 선택하면 unit은 corridor, time.freq는day로 두고 원자료 시간 필터는 정제 단계에 기록한다. 날짜 인덱스는 휴일을 삭제한 뒤 재번호를 매기지 않고 실제 달력 간격을 유지한다. 엔진 스키마에 없는 수동 보류 조건은 가정·해석 문서와 실행 점검에 기록하고 검증기를 통과시키기 위해 지우지 않는다.

에이전트는 네 가지 작업에 활용한다. 수집 에이전트는 파일과 출처를 확보하고, 정제 에이전트는 시간·ID·단위 검사를 만들며, 실험 에이전트는 고정 설정으로 모델을 실행하고, 검토 에이전트는 누출과 해석을 독립 점검한다. 처치·기간·비교군·주 지표의 변경은 변경 기록을 남긴다. GPU는 학습 작업 하나씩 배정하고 수집·검증은CPU로 진행한다.

사전 자료를 이용한 비교군 선정 절차 자체도 먼저 기록한다. 최종 효과를 보기 전에 링크·기간·지표·비교군을 동결한다. 원자료와 가공 행 단위 자료는 저장소에 커밋하지 않는다. 계획 커밋·결과 커밋의 간격 등은 첨부 README와 저장소의 실제 운영 기준을 따른다.

# 9 단기 일정과 축소 기준

| 작업일 | 수행 | 완료 증거 |

| 1\~2 | 정책 지도·링크 연결, 데이터 사전·이력 확인 | 처치 후보 지도와 미확인 항목 |

| 14\~15 | 민감도·해석·재현 실행·PR 정리 | README로 재현 가능한 결과 |

3일차에 자료 정의와 핵심 링크 확인이 해결되지 않으면 질문을 축소한다.10일차까지CPU 결과와 주 분석 보고를 완성하는 것을 우선한다. 시간이 부족하면 대시보드·그래프 신경망·foundation model 비교 순서로 확장을 줄인다.

| 문제 | 대응 |
| - | - |
| 적합한 비교군을 확인하지 못함 | 관측된 전후 변화와 한계로 정책 보고를 완성하고 인과 결론 보류 |
| 양재천 도로망 변화·수요 정책의 차별적 영향이 분리되지 않음 | 버스 정책 단독 효과로 귀속하지 않음 |
| 시간 열·특수값 정의가 불명확 | 해당 주 지표 계산을 보류하고 정의부터 확인 |
| 메타데이터·유효 관측이 전후 달라짐 | 동일 의미 링크로 좁히거나 분석 범위를 수정해 기록 |
| 2023년 데이터 확보 지연 | 2024년 상반기 예측으로 축소하고 계절 일반화 제한 |
| GPU 환경 복원에 시간이 오래 걸림 | CPU 모델 결과 유지, DLinear로 작은 학습 실험 |
| 딥러닝이 기준선을 이기지 못함 | 성능·비용 비교를 그대로 보고 |

완료 기준은 유의한 정책 효과나 딥러닝의 승리가 아니다. 근거·데이터·평가·한계를 재현 가능한 형태로 연결하는 것이다.

# 10 다음 행동과 필요한 자료 요청

1. **정책과 링크를 연결한다.** 세 핵심 링크의 당시 정류장·가로변 이동·재합류 위치를 확인하고 북향·양재 이남의 역할을 기록한다. 현재 지도만 있을 경우 역사적 구간 검증의 근거를 별도로 남긴다.

2. **TOPIS에 정의와 이력을 확인한다.** 시간 열·날짜 귀속·단위·0/결측·보정·표본 변경,2024 유효 링크 지오메트리와 변경 이력,자료 사용·공개 조건을 요청한다. 답변이나 공식 문서가 확보되면 정제 규칙을 확정한다.

3. **계획을 동결한다.** 비교 후보의 노선·우회·공사 노출 검토와 사전 선정 절차를 기록한 뒤 causal plan과 ML plan을 따로 확정한다. 자동 검정과 별도로 판단 보류 조건을 둔다.

4. **필수 자료를 단계적으로 수집한다.** 정책용2024년4\~8월을 먼저 완성하고, ML용2023년1월\~2024년8월20개월로 확장한다. 기상·공휴일은 공식 파일이나API로 연결한다. 교통량은 보조 과제다.

5. **CPU 결과를 먼저 만든 뒤GPU 학습을 실행한다.** 같은 시간 분할로 기준선·CatBoost·PatchTST를 비교하고, 정책 후 예측오차를 인과효과로 해석하지 않는다.

사용자에게 필요한 추가 정보는 마감일, 주당 투입 가능 시간, 현재RAM과 실행환경 정도다. GPU 모델명은 이미 알려준RTX5070 Ti16GB를 사용한다. TOPIS 월별 파일을 사용자가 일일이 다시 찾아 줄 필요는 없다. 기상자료는 인증키를 로컬에 설정하거나 공식 다운로드 파일을 전달하면 된다.

기관 요청 항목은 세 묶음으로 줄일 수 있다.

- **속도 자료 사전:** 2023\~2024 XLSX 시간·날짜·단위·집계·결측·보정·표본 정의.

- **운영과 공간 이력:** 2024년6월 전후 링크·정류장·노선·공사·신호·차로 변경. D-35·D-43은 교통량을 추가할 때 확인.

- **이용 조건:** 학생 연구·모델학습·집계 결과·코드·모델 가중치 공개 범위.

기관에 실제 문의를 발송한 상태는 아니다.

다운로드 성공 여부만으로 분석 준비 완료를 선언하지 않는다. 수집 시점·응답·파일 형식·해시·헤더를 기록하고 구조가 바뀌면 멈춘다.

이번 조사에서 기존 정책 안내에 포함된 명동 선행 조치 평가,7월25일 국토부 버스 성과 발표의 제목·요약,기후동행카드 설명자료의 성과 수치를 접했다. 이를 주 지표·기간·비교군·효과 방향을 선택하는 기준으로 사용하지 않는다. 실제5월·7월XLSX에서는 속도 숫자를 분석하지 않고 메타데이터와 헤더만 확인했다.

이 계획의 핵심 미확인 사항은 노선별 실제 첫 적용·예외,시간과 특수값 사전,월별 자료 이용조건,2024 공간 이력,검증된 비교군,동시 변화의 차별적 영향이다. 이를 해결한 수준에 맞춰 정책 분석의 해석 강도를 정한다.
