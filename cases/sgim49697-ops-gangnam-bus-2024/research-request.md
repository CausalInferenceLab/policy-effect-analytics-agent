# 외부 AI 요청서: 강남대로 광역버스 분산 정책의 자료 조사와 설계 검토

이 문서 전체를 복사해 외부 AI에 전달하면 된다. 아래는 다른 대화나 첨부 없이 사용할 수 있는 요청 본문이다.

## 요청 목적과 배경

나는 공공데이터 강의의 학생 참여자로, 정책 효과 분석 프로젝트를 직접 만들어 공동 저장소에 PR로 기여하려고 한다. 아래 주제가 실제로 수행 가능한지 자료와 근거를 조사하고, 무리하지 않은 분석 설계를 추천해 달라. **지금 필요한 것은 출처 확인과 설계 검토이며, 정책 효과를 계산하는 작업은 아니다.**

- 연구 질문: 2024년 6월 29일로 안내된 강남대로 광역버스 운행 조정 이후, 평일 퇴근 시간대 일반 차량의 교통 흐름은 비교 도로에 비해 어떻게 달라졌는가?
- 우선 범위: 강남대로 정책 영향 구간과 비교 가능한 도로, 평일 퇴근 시간대. 17~20시는 후보이며 확정값이 아니다.
- 난이도 목표: 기본적인 데이터 정리·시각화·정책 전후 비교를 경험할 수 있는 중간 수준의 학생 프로젝트. GPU는 이용할 수 있지만 사용 자체가 목표는 아니다.
- 확정 전인 항목: 대상 링크·방향, 비교 도로, 전후 기간, 주 지표, 집계 방식, 추론 방법.
- 효과 방향: 개선·악화·판단 불가 모두 가능하다. 원하는 결론에 맞추지 말아 달라.

## 조사해 줄 내용

### 1. 정책이 실제로 언제, 어디에서 바뀌었는가

- 발표일, 안내상 시행일, 실제 적용일을 구분하고 유예·후속 변경·추가 조치 여부를 확인해 달라.
- 강남의 노선·운행 방향·차로·정류장 조정을 분리해 정리하고 각 조정의 시간대와 공간 범위를 제시해 달라. 명동 정책은 별도 표기해 달라.
- 당시 노선도·정류장 위치·공식 공고로 영향 구간을 설명해 달라. 강남대로 전체나 한 방향 전체를 근거 없이 처치로 지정하지 말아 달라.
- 당시 자료를 찾지 못하면 현재 노선·링크 정보를 과거 정보로 대체하지 말고 확인 불가로 남겨 달라.

### 2. 어떤 자료를 어떻게 확보할 수 있는가

- 월별 속도 파일, 링크 위치·길이·방향과 변경 이력, 필요할 경우 기상·공휴일·교통량 자료의 공식 출처와 접근 방법을 조사해 달라.
- 자료별 제공 기간, 관측 단위, 파일 형식, 접근·인증 조건, 실제 확인 범위와 이용·재배포 조건을 표로 정리해 달라.
- TOPIS 시간 열이 시작시각인지 종료시각인지, `~24시`와 날짜가 어떻게 연결되는지 확인해 달라. 다른 기관의 시간 규칙을 그대로 적용하지 말아 달라.
- 속도·거리 단위, 평균 방식, 결측·0값·이상값·보정값의 정의와 연도별 생성 방식 변경을 찾아 달라. 문서가 없으면 추측하지 말아 달라.
- 링크 ID가 기간 내 같은 구간을 뜻하는지 확인할 자료와 절차를 제안해 달라. 파일 전체의 수치 분석은 하지 말고 목록·메타데이터·헤더 수준에서 가용성을 판단해 달라.
- 데이터 자체의 이용 조건을 찾아 달라. 정책 안내문의 저작권 표시나 사이트 공개 여부로 데이터 이용 조건을 대신하지 말아 달라.

### 3. 무엇과 비교하면 설득력이 있는가

- 비교 도로 후보를 근거와 함께 소수 제안하고, 도로 기능·방향·연결성·정책 노출·우회 영향·관측 가능성을 비교해 달라. 후보를 검증된 비교군으로 표시하지 말아 달라.
- 반대 방향이나 주변 도로도 정책의 영향을 받을 수 있다. 비처치로 볼 근거와 제외해야 할 상황을 구분해 달라.
- 정책 이전 자료를 이용한 비교군 선별과 사전 추세 점검을 어떻게 사전에 정할지 제안해 달라. 사후 결과에 맞춰 비교군을 바꾸는 방식은 피해야 한다.
- 적절한 전후 기간과 전환기·휴일 처리 방안을 추천하고, 자료 가용성과 동시 변화에 근거를 두어 달라.

### 4. 같은 시기에 다른 변화가 있었는가

- 2024년 정책 전후 강남대로와 비교 후보 도로의 공사·신호·차로 운영·버스 노선·정류장 변경을 조사해 달라.
- 기후동행카드, K-패스 등 교통정책과 장마·방학·휴일은 검토할 항목의 예다. 실제 시점과 대상, 이 연구에서 혼동 요인이 될 경로를 각각 확인해 달라.
- 연표에 발표와 실제 시행을 구분하고, 서울 전체 공통 변화인지 대상 도로에 다른 영향을 줄 변화인지 설명해 달라. 찾지 못한 사실은 변화가 없었다는 증거로 쓰지 말아 달라.

### 5. 중간 난이도에서 어떤 분석이 적절한가

- 주 지표를 속도 또는 고정 경로의 추정 통행시간 중 하나로 추천하고, 측정 대상·단위·구간과 시간 집계·가중치의 이유를 설명해 달라.
- 여러 링크의 평균 속도를 단순 평균해 경로 이동시간으로 해석하지 않도록 주의해 달라. GPS 기반 일반도로 속도에서 버스 승객 이동시간이나 차로별 효과를 직접 알 수 있다고 가정하지 말아 달라.
- DiD와 이벤트 스터디가 가능한지 검토하고, 가능하다면 필요한 가정과 최소 진단을 설명해 달라. 불가능하면 그 이유와 축소 가능한 질문을 제시해 달라.
- 하나의 정책 영향 도로를 여러 독립 처리 지역으로 세지 말아 달라. 시간·공간 상관, 적은 처리 단위, 비교군 배정 가정에 맞는 불확실성 평가를 검토해 달라. 엔진의 무작위화 추론 기능만으로 문제가 해결된다고 가정하지 말아 달라.
- 교통량이 정책 변화의 결과나 경로가 될 가능성을 검토하고 통제변수로 자동 투입하지 말아 달라. 오전·야간 역시 비처치라는 근거 없이 위약 시간대로 지정하지 말아 달라.
- 사전 추세·가짜 시행일·민감도 점검과 판단 보류 조건을 제안해 달라. 검정 통과를 인과효과의 증명으로 설명하지 말아 달라.
- 우선 한 가지 실현 가능한 설계를 추천해 달라. 딥러닝·GPU·대시보드 구현을 필수 단계로 늘리지 말아 달라.

## 원하는 답변 형식

다음 순서로 한국어 보고서를 작성해 달라.

1. **실행 가능성 판단:** 진행 가능 / 조건부 가능 / 현재 근거로 보류 중 하나와 핵심 이유.
2. **근거 표:** 확인된 사실 / 설계 제안 / 미확인 사항을 구분. 각 사실에는 원문 URL, 문서 제목·발행일, 확인 날짜, 해당 절·표·페이지 또는 짧은 인용을 붙인다. 재인용 기사보다 원문을 우선하고 접근하지 못한 자료는 명시한다.
3. **정책 연표와 공간 범위:** 노선·방향·시간대·구간의 관계와 TOPIS 링크 연결에 필요한 추가 자료. 모르는 코드나 좌표를 만들지 않는다.
4. **데이터 확보 표:** 자료명, 기간·단위·정의, 접근 방법, 이용 조건, 실제 확인 범위, 남은 확인 절차.
5. **권장 설계 하나:** 주 지표, 분석 단위·시간대·기간, 비교 도로 후보, 방법, 진단과 해석 한계. 가정과 미정 사항을 표시한다.
6. **위험과 대응:** 분석을 막는 문제와 한계를 명시하고 진행할 수 있는 문제를 구분. 인과 해석을 보류할 구체적 조건을 적는다.
7. **다음 행동 최대 다섯 개:** 각 행동이 어떤 미정 사항을 해결하는지, 어떤 증거가 나오면 계획을 확정할 수 있는지 적는다.

효과 크기·유의성·그래프·모델 학습·분석 코드는 이번 답변의 범위에 포함하지 않는다. 검색 결과의 요약만 보고 원문을 확인했다고 쓰거나, 사후 결과가 잘 나오는 기간·지표·비교군을 고르지 말아 달라. 결과 수치가 포함된 기존 평가를 접했다면 그 열람 사실을 별도로 표시하고 설계 선택의 정답으로 사용하지 말아 달라.

## 답변을 받은 뒤의 반영 기준

프로젝트 작성자가 원문을 다시 확인한 내용만 `plan.md`의 확인된 사실로 옮긴다. 설계 제안은 근거와 한계를 검토해 채택하거나 보류하고, 확인하지 못한 내용은 미정으로 유지한다. 처치·비교군·기간·지표·진단을 결정한 뒤 실행용 `plan.yaml`을 먼저 기록하고 실제 자료 분석으로 넘어간다.
