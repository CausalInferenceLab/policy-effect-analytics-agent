## 1. 목적과 완료 기준

> 2024년 6월 29일로 안내된 강남대로 광역버스 운행 조정 이후, 평일 퇴근 시간대 일반 차량의 교통 흐름은 비교 도로에 비해 어떻게 달라졌는가?

정책 근거 확인부터 데이터 수집·검증·전후 비교·한계 설명까지 직접 수행하는 학생 프로젝트다. 효과의 방향은 미정이다. 교통 흐름이 개선되는 결과뿐 아니라 악화되거나 판단하기 어려운 결과도 그대로 보고한다.

이번 구현의 범위는 실행 설정, 수집·검증·정책 비교·모델 학습 코드와 합성 입력 검증이다. 사용자의 결정에 따라 고정 마감 없이 단계별로 진행하며, DLinear·PatchTST·Chronos2와 조건부 그래프 모델까지 포함한다. 프로젝트 전체의 완료 기준은 공개 출처와 수집 코드로 실제 분석을 재현하고 해석의 한계를 설명하는 것이다. 코드를 구현한 것과 실자료 연구를 완료한 것을 구분한다.

## 2. 정책 근거와 해석 범위

아래 내용은 [서울시 정책 안내](https://mediahub.seoul.go.kr/archives/2011484)의 「① 강남대로 운행방향」·「② 강남대로 중앙차로」·「③ 성남-명동」 부분을 확인한 요약이다. 발행일은 2024-06-18, 수정일은 2024-06-19다. 안내문 확인과 실제 운영 이력 검증을 구분한다.

| 항목 | 확인한 내용 | 추가 확인 |
|---|---|---|
| 안내상 시행일 | 2024-06-29 | 실제 첫 적용, 유예·예외·후속 변경 |
| 연구 대상 | 전체 22개 중 강남 방향 20개 노선 | 적용 구간과 방향을 당시 도로 링크에 연결 |
| 조정 구성 | 5개 노선의 오후 운행 방향 변경, 15개 노선의 일부 가로변 차로 이용, 정류장 재배치 | 노선별 적용 시간과 구간, 구성별 중첩 |
| 별도 정책 범위 | 명동 방향 2개 노선은 이번 연구 대상에서 제외 | 비교 도로 선정 시 관련 우회 영향 점검 |

우선 노선·차로·정류장 조정이 함께 이루어진 정책 묶음을 연구한다. 그중 한 요소만의 효과로 분리해 설명하려면 별도 근거와 설계가 필요하다.

TOPIS 일반도로 속도를 교통 흐름의 대리 지표로 사용한다. 버스 자체의 속도, 승객의 문전 간 이동시간, 중앙차로와 가로변 차로 각각의 혼잡, 배출량·후생은 이 자료만으로 직접 측정하지 않는다. 개선과 악화가 동시에 생기거나 구간·방향에 따라 다를 가능성을 열어 둔다.

## 3. 데이터와 확인 이력

아래 표는 **2026-10-27 최초 조사 시점**의 기록이다. 2026-10-28에 2023년 1월~2024년 8월 원본 20개를 모두 수집했다. 최신 확인 사항·미해결 정의는 [근거 기록](evidence.md), [데이터 계약](data_contract.yaml), [다운로드 매니페스트](source-manifest.json)를 기준으로 삼는다. 원본은 로컬 Git 제외 폴더에 보관하고 속도 수치는 집계하지 않았다.

| 자료 | 현재 확인한 내용 | 미확인 사항 |
|---|---|---|
| [TOPIS 속도 정보](https://topis.seoul.go.kr/refRoom/openRefRoom_1.do) | 안내상 일반도로는 카드택시 GPS 기반 구간 속도. 도로별 일자별 통행속도 월별 파일 제공 | 2024년 생성·보정 방식, 결측 의미, 표본 변화, 이용 조건 |
| 같은 페이지의 2024년 파일 목록 | 1~12월에 해당하는 12개 게시 항목 확인 | 전 파일 다운로드 성공, 내용 완전성, 필요한 모든 링크의 연속 관측 |
| `2024년 5월 서울시 차량통행속도.xlsx` 사전 구조 확인 | 일자·요일·도로명·링크아이디·시점명·종점명·방향·거리·차선수와 `~01시`부터 `~24시`까지의 열. 강남대로 관련 문자열 존재 | 정확한 처치 링크, 시간 구간의 시작·종료 기준, 거리 단위, 링크 변경 이력 |
| [TOPIS 교통량 정보](https://topis.seoul.go.kr/refRoom/openRefRoom_2.do) | 지점·방향·시간대별 자료 제공 안내 | 분석 구간과 관측 지점의 대응, 필요한 기간의 가용성. 보조 지표 후보 |

2024년 목록은 TOPIS 웹페이지가 사용하는 `POST /refroom/selectRefRoomListASC.do`에 `blbdDivCd=06`, `bdwrDivCd=2024`, `mainBdwrRowNum=12`를 전달해 확인했다. 5월 게시물의 `bdwrSeq`는 `4171`이다. 이는 조사 경로 기록이며 안정성이 보장된 공개 API 명세로 간주하지 않는다.

**사전 열람 공개:** 주제 선정 과정에서 5월 파일을 메모리로 열어 헤더와 도로명 문자열을 확인했다. 해당 파일의 속도 수치 탐색·집계·그림 작성과 정책 효과 추정은 하지 않았다. 정책 안내에 다른 지역의 기존 성과 설명이 포함되어 있음을 인지하며, 이를 이 연구의 기대 효과나 결과로 사용하지 않는다. 이번 문서 작성에서는 공식 안내와 게시 목록을 재확인했다. 원자료를 저장소에 추가하지 않았다.

자료의 이용·재배포 조건은 아직 확인하지 못했다. 정책 설명 페이지의 저작권 표시를 TOPIS 데이터에도 적용하지 않는다. 원자료와 가공 데이터는 저장소 규칙에 따라 커밋 대상에서 제외한다.

## 4. 최초 설계 후보와 해석 원칙

아래 후보 표는 초기 조사 기록이며, 선택한 실행 규칙은 **7절과 YAML 설정**에 고정했다. 초기 표의 미정 항목을 그대로 실행 규칙으로 쓰지 않는다.

| 결정 항목 | 현재 상태 | 확정 전에 필요한 근거 |
|---|---|---|
| 주 분석 시간 | 평일 퇴근 시간대. `17:00 ≤ 시각 < 20:00`은 검토 후보 | 운행 시간, TOPIS 시간 표기와 대응, 공휴일 처리 |
| 공간 범위 | 강남대로의 정책 영향 구간·방향 | 당시 노선·정류장 지도와 링크 연결. 강남대로 전체를 자동 처치하지 않음 |
| 자료 단위 | 링크 × 날짜 × 시간 자료를 출발점으로 검토 | 최종 분석 단위와 구간·시간 집계 기준 |
| 주 결과 지표 | 속도 또는 고정된 경로의 추정 통행시간 중 하나를 선택할 예정 | 측정 정의, 거리·속도 단위, 링크 연결성과 결측 처리 |
| 전후 기간 | 미정. 2024년 정책 전후 자료를 우선 검토 | 선행 조치·후속 변경·계절성과 자료 가용성 |
| 비교 도로 | 미정 | 비처치 근거, 도로 특성, 교통 수요, 우회·연결 영향 |
| 방법 | 이중차분(DiD)과 이벤트 스터디의 적용 가능성 검토 | 비교 가능성, 처리 단위 수, 시간·공간 상관을 고려한 불확실성 계산 |
| 보조 분석 | 오전·다른 시간대와 교통량은 후보 | 정책 영향을 받지 않는 시간대라는 근거 없이 위약 검정으로 지정하지 않음 |

정책이 없었더라면 대상 도로에서 일어났을 변화와의 차이를 질문한다. 단순 전후 차이는 계절·기상·다른 교통 변화도 포함하므로 그 자체를 정책의 인과효과로 해석하지 않는다.

속도를 경로 통행시간으로 바꾼다면 연결된 고정 경로에서 링크별 거리/속도로 얻은 소요시간을 합산할 수 있는지 먼저 확인한다. 여러 링크의 속도를 단순 평균한 뒤 전체 거리로 나누지 않는다. 시간별 속도 통계로 계산한 값은 실제 차량의 완주시간과 같다고 가정하지 않는다. 지표·가중치·시간 집계 방식은 결과를 보기 전에 정한다.

여러 링크와 많은 시간 관측값이 있어도 하나의 정책을 받은 도로를 독립된 처리 지역 여러 곳으로 세지 않는다. 저장소의 소수 처리 지역용 추론 기능을 사용할 수 있더라도 그 기능만으로 비교군과 배정 가정의 타당성이 확보되지는 않는다. 교통량은 정책으로 변할 수 있으므로 자동으로 통제변수에 넣지 않는다.

## 5. 외부 검토에서 해소할 질문

| 우선순위 | 질문 | 계획에 미치는 영향 |
|---|---|---|
| 필수 | 어떤 방향·구간이 언제 실제로 바뀌었나? | 처치 정의·시점 |
| 필수 | 필요한 링크가 정책 전후 같은 의미로 관측되나? `~24시`, 0, 결측은 무엇을 뜻하나? | 분석 단위·시간 정렬·측정 가능성 |
| 필수 | 정책이나 우회 영향이 없다는 근거를 가진 비교 도로가 있나? | 비교 설계 가능성 |
| 필수 | 시행 전후 공사·신호·버스 운영·다른 교통정책 변화가 겹치나? | 기간·제외 기준·효과 해석 |
| 필수 | 소수 도로와 상관된 관측에서 불확실성을 어떻게 설명할 것인가? | 추론 방법·판단 보류 기준 |
| 필수 | 데이터 이용 조건과 재현 가능한 접근 경로는 무엇인가? | 수집·공개 범위 |
| 보완 | 오전·다른 시간대·교통량을 어떤 보조 질문에 사용할 수 있나? | 확장 범위 |

조사 방법과 원하는 답변 형식은 [외부 AI 요청서](research-request.md)에 적었다. 기후동행카드·K-패스 등 다른 교통정책과 장마·휴일·방학은 확인할 요인의 예이며, 여기서는 정확한 시점이나 강남대로 영향이 검증된 것으로 취급하지 않는다.

비교 도로의 선정·배제 규칙과 사전 추세 진단 기준을 먼저 기록한다. 이후 진단이 좋지 않다고 결과에 유리한 비교군으로 계속 바꾸지 않는다. 사전 추세 검정의 비유의성도 평행추세를 증명하지 않는다. 기상·휴일 등 보조 자료는 필요성과 공식 출처를 확인한 뒤 추가한다.

## 6. 다음 단계로 넘어가는 기준

실자료 분석을 시작하기 전에 다음의 근거를 확인한다. 설계 선택은 작성됐지만 근거 관문이 모두 통과된 것은 아니다.

- 처치일·구간·방향·링크 목록, 비교군과 배제 이유, 정책 전후 기간과 전환기 처리.
- 주 지표 하나, 집계·가중치·결측 규칙, 요일·공휴일·시간대의 정확한 정의.
- 비교 설계, 사전 추세와 가짜 시행일 등의 진단, 시간·공간 상관을 고려한 추론과 판단 보류 조건.
- 자료 접근 경로와 이용 조건, 메타데이터 연결 검증 방법, 외부 답변을 원문으로 확인한 기록.

처치 구간 연결이 불가능하거나 비교군의 정책 노출을 구분할 수 없는 경우, 중요한 동시 변화와 측정 변경을 분리할 수 없는 경우에는 인과효과 분석을 보류한다. 근거가 부족한데 모형을 복잡하게 만들어 결론을 내지 않는다. 기술적 전후 비교로 범위를 줄이면 계획 변경으로 기록하고 해석도 그 범위에 맞춘다.

외부 검토 내용을 바탕으로 [계획 작성 가이드](../../docs/strategy/plan-guide.md)에 맞는 `plan.yaml`을 작성했다. 계획 PR과 구현 PR을 분리했다. 최초 확증 설계는 최종 설정 커밋 후 24시간과 자료 관문을 요구했으나, 이번 실행에는 아래의 명시적 탐색 분석 규칙을 적용한다. 결과를 본 뒤 설정을 바꾸면 변경 이유와 탐색 분석 여부를 기록한다. GPU 예측 실험을 포함하며 별도 웹 서비스는 범위에 없다.

## 7. 고정한 실행 규칙

### 정책 비교

- 원점 `2024-05-20`의 달력 날짜 차이를 `day_idx`로 사용한다. 주말·공휴일·전환기를 제거한 뒤 순번을 다시 매기지 않는다.
- 처치 1곳: 교보타워사거리→강남역→우성아파트→뱅뱅사거리. 링크 `1220025000`, `1220021000`, `1220016200`의 고정 거리 비율 `776:586:414`를 사용한다. 실제 경로 평균속도나 버스 속도가 아닌 **길이가중 산술 속도지수**다.
- 시간: 공휴일 제외 평일 `17:00 ≤ 구간 시작 < 20:00`. 세 링크×세 시간의 9개 값이 모두 유효한 날만 사용한다. 결측 보간·가중치 재분배를 하지 않는다.
- 전: `2024-05-20~06-28`. 전환기 제외: `06-29~07-07`. 후: `07-08~08-16`. 안내상 시행일은 `06-29`이며 첫 운영 주 제외는 설계 선택이다.
- 비교 후보는 동작대로 이수역→사당역, 송파대로 석촌역→가락시장역, 시흥대로 구로디지털단지역→시흥IC. 방향·링크는 [corridors.yaml](corridors.yaml)에 기록했다. 비노출·공사·우회 영향은 아직 미확인이다.
- 후보는 각각 전후 유효일 비율 80% 이상, 전후 비율 차이 10%p 이하를 통과해야 한다. 통과한 후보를 전부 쓰고 결과에 따라 골라내지 않는다. 공통 날짜가 전후 각각 20일 이상이며 비교 도로가 2곳 이상일 때만 비교 추정을 한다. 미달하면 기술통계만 남긴다.
- 주 추정은 균형 패널의 도로·날짜 고정효과 DiD. 개인 실행기는 동일한 계수인 평균 격차의 전후 차이를 계산한다. 주별 격차는 직전 주 `-1` 대비 진단이며, 가짜 시행일 `06-10`은 원래 사전 기간에서만 계산한다.
- 민감도: `06-17~28` 제외, `07-01`부터 포함, 양재역 링크 확장, 비우천일, 비교 도로 하나씩 제외. 주 분석의 비교군을 고정한다. 짧아지는 발표 기간 제외·비우천 분석은 전후 10일 이상을 요구하며 별도 표시한다.
- 처치 도로가 1곳이므로 판정은 `not_identified`. 공통 엔진의 순열 반복 횟수나 유의확률을 독립 도로 수 대신 쓰지 않는다. 개인 실행기는 p값·신뢰구간을 인과 결론으로 제공하지 않는다. 장마·기후동행카드·양재천 우안도로 등 동시 변화는 남은 한계다.

### 예측 실험

| 분할 | 모든 링크에 공통인 기간 |
|---|---|
| 학습 | 2023-01-01~2024-03-31 |
| 검증·설정 선택 | 2024-04-01~04-30 |
| 최종 정책 전 평가 | 2024-05-01~06-16 |
| 전환 구간 별도 평가 | 2024-06-17~06-30 |
| 최종 정책 후 평가 | 2024-07-01~08-31 |

- 24시간 시계열을 유지한다. 발행시각 `t`에 이미 끝난 `t-168~t-1`의 168개 시간 구간을 입력한다. 1시간 예측은 `[t,t+1)`, 3시간 예측은 `[t+2,t+3)`다. 출력 3개 구간 모두 같은 분할 안에 있고 실측일 때만 공통 평가 창으로 쓴다.
- 네 후보 도로의 링크 중 메타데이터 일관성을 확인하고 **학습 기간** 관측률 95% 이상인 링크를 고른다. 핵심 3개는 필수다. 나머지는 ID 순서로 최대 100개까지 사용한다. 사후 점수로 링크를 고르지 않는다.
- 입력은 과거 방향으로 최대 3시간 채우고 남은 결측은 학습기간 링크별 요일·시간 평균, 해당 셀이 없으면 학습기간 링크 평균을 쓴다. 원래 관측 마스크를 보존하고 입력 창의 원관측률이 95% 미만이면 제외한다. 정답은 채우지 않는다.
- scaler·요일시간 평균은 학습 기간에서만 적합한다. 검증·시험 입력은 이전 분할의 과거 맥락을 사용할 수 있다. 미래 실제 날씨·이웃 링크의 미래 값은 사용하지 않는다.
- 9개 모델: 마지막 값, 주간 계절 기준선, 요일시간 평균, CatBoost CPU, DLinear, PatchTST, Chronos2 zero-shot, DCRNN, STGCN. 그래프 모델은 학습·평가 전체 기간에 유효한 연결표가 있어야 한다.
- NeuralForecast 3.3.0의 DLinear·PatchTST 네트워크를 사용하되 학습 창·마스크·scaler·조기 종료는 개인 코드로 관리한다. DCRNN·STGCN은 논문 구조를 참고한 작은 PyTorch 구현이며 원저자의 성능 재현을 주장하지 않는다. STGCN은 연결을 대칭화하고 마지막 시간 표현으로 3시간을 직접 출력한다.
- 후보 설정은 [ml_config.yaml](ml_config.yaml)에 고정했다. 검증 1시간 MAE로 seed 17에서 선택하고 선택 설정을 17·42·2026으로 반복한다. 최종 모델은 검증 기간을 합쳐 재학습하지 않는다. 신경망은 최대 50 epoch 또는 10,000 step, 조기 종료 5회, 시작 batch 16이며 OOM이면 줄여 재시작·기록한다.
- 주 지표는 1시간 MAE(km/h). 3시간 MAE, RMSE, 퇴근 시간·핵심 구간·링크별 성능, seed 표준편차, 시간·VRAM·모델 규모를 함께 남긴다. 모든 모델의 평가 키와 실측 정답이 같아야 비교 파일을 생성한다.
- Chronos2는 고정된 모델 revision의 중앙값 예측을 사용한다. 외부 사전학습 자료와 평가 기간의 중첩 여부가 불명하므로 별도 비교군으로 표시한다. 정책 후 실제 과거 속도를 입력한 예측을 무정책 반사실로 해석하지 않는다.

## 현재 실행 방식: 탐색 분석

2026-10-28 사용자가 즉시 수집·학습·결과까지 진행하도록 요청했다. 위 최초 설계와 아래 과거 기록의 24시간 대기와 미확인 항목 중단 방침은 이번 **탐색 분석**에 한해 대체한다. 미확인 사실을 검증 완료로 바꾸지 않는다. 설정은 실측 속도 집계 전에 다시 커밋하며, 원래 확증 계획은 `d52ca52`에 보존한다.

- 두 시간 헤더를 종료시각으로, 속도를 km/h로 해석한다. 정책 저녁 창을 ±1시간 이동한 민감도를 함께 낸다.
- 0·음수·빈칸은 주 분석에서 결측으로 둔다. 원인별 개수와 0을 유효값으로 두는 정책 민감도를 보고한다.
- 시종점 이름 변경 4개 링크를 제외하고, 차선 수 변경은 기록한 채 사용한다. 측정 환경이 일정했다고 주장하지 않는다.
- 도로 비교군과 추가 양재역 링크는 메타데이터를 대조한 탐색 후보다. 비노출·동시 공사를 검증한 대조군이 아니므로 판정은 `not_identified`다.
- 그래프는 전체 월에 안정적인 동일 도로·방향의 시종점 이름으로 유도한다. 실제 회전 가능성을 검증한 역사적 도로망으로 표현하지 않는다.
- DLinear·PatchTST·STGCN은 최대 1,000 step, DCRNN은 300 step, CatBoost는 train에서 seed 17로 고른 최대 20만 창·800회로 제한한다. 후보 설정과 3개 seed는 유지한다. 수렴 실험이나 같은 계산량 경쟁이 아니다.
- 기간 분할·train 전용 전처리·모든 모델의 동일 평가 창은 유지한다. Chronos2는 외부 사전학습 모델로 구분한다.
- TOPIS 월별 파일의 개별 이용 조건은 미확정이다. 원본·가공 행·체크포인트는 공개 저장소에 올리지 않고 출처·코드·요약 통계·자체 작성 그림만 남긴다.
