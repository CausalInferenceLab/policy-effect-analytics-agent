# 동시 정책·관련 연구·다년 원본의 해석 점검

작성일: 2026-10-29. 이 문서는 야간 확장 탐색 E01·E03·E12의 추가 근거다. 기존 수치와 동결된 예측 시험을 바꾸지 않는다. 원문 다운로드의 출처·해시는 [명세](overnight-context-sources.json)에 있으며, PDF·HTML 원문은 Git에 올리지 않는다.

## 이번 확인이 분석 방향에 미치는 영향

**강남대로 남·북행의 서로 다른 변화는 계속 분석할 가치가 있지만, 6월 29일 정류장·노선 조정의 단독 효과로 발표할 근거는 부족하다.** 같은 날 GTX-A 구성역이 열렸고, 7월에는 서울 면허 버스의 요금상품이 바뀌었다. 카드·환승·운행 기록을 함께 보되 각 자료의 수록 범위와 분모를 먼저 구분하는 방향을 채택한다.

2022년 운행시간 자료는 비교 기준 연도를 늘리는 데 사용할 수 없다. 전체 행 검사에서 빈 파일과 형식 오류가 확인됐고, 형식이 정상인 날짜만으로도 필요한 사전·사후 20일을 충족하지 못한다. 반면 2023~2025년 기존 사용 원본에서는 이미 격리한 두 주간 파일 외에 추가 구조 오류가 발견되지 않았다.

청년 할인은 7월에 처음 생긴 혜택이 아니다. 시범사업 기간의 환급 방식과 본사업의 충전 시 할인 방식을 구분한다. 또한 8월 FAQ는 8월 10일부터 진접선·별내선까지 카드 이용범위가 확대될 예정이라고 설명한다. 정책 조정 뒤의 환경이 계속 동일했다고 가정하지 않는다.

이 날짜들이 같거나 가깝다는 사실은 **혼입 가능성의 근거**다. 각 변화가 강남대로 수치에 얼마나 기여했는지는 이 자료만으로 나누어 식별하지 못한다. 동시 정책을 나열한 뒤 회귀식에 사후 더미 여러 개를 넣는 것만으로 문제가 해소되지 않는다.

후속 민감도는 결과 계산 전에 별도 규칙으로 기록한다. 우선 2023년 요금 인상 이전인 8/11까지만 남긴 참고 비교, 노선군·정류장별 승차와 환승 변화, 주변 일반도로·교통량의 동시 움직임을 확인한다. 2023년을 자동으로 무처치 대조군으로 삼지 않는다.

## 2022년 자료가 비교에 부적합한 이유

2022년 4~8월 운행시간·운행횟수 ZIP 10개의 **17,479,156행 전체**를 검사했다. CSV 첫 행만 확인하지 않고 모든 행의 열 수와 날짜 형식을 비교했다.

| 자료·월 | 발견한 구조 | 판정 |
|---|---|---|
| 운행시간 4월 | 4개 주간 파일의 행 너비가 31/33열로 파일 내부에서도 달라짐 | 뒤쪽 열 의미가 확인되지 않아 임의 제거·보정하지 않음 |
| 운행시간 5월 | 3개 비어 있지 않은 파일의 날짜 헤더가 손상, 2개는 빈 파일 | 제외 |
| 운행시간 6월 | 2개 빈 파일, 2개 형식 적합 파일 | 일부 날짜만 존재 |
| 운행시간 7월 | 4개 형식 적합 파일 | 일부 날짜만 존재 |
| 운행시간 8월 | 5개 모두 빈 파일 | 비교 불가 |
| 운행횟수 4~8월 | 월별 5개 모두 형식 적합, 153개 날짜 | 운행시간 자료의 부재를 보완하지 못함. 별도 질문에는 추가 검토 가능 |

형식이 적합한 운행시간 날짜는 총 30일이다. 같은 달·일의 사전 창 5/20~6/28에는 **평일 7일**, 사후 창 7/8~8/16에는 **평일 11일**뿐이다. 이는 공휴일을 빼기 전 상한이므로 기존 최소 20일 조건에 도달할 수 없다. 2022년 정류장·노선 이력을 추가 확인해도 이 날짜 부족은 해결되지 않는다.

기상청 교육자료의 2022년 8월 8일 사례도 당시 집중호우를 다룬다. 이는 오래된 같은 계절을 무조건 안정된 참고 연도로 삼기 어렵다는 맥락이다. 이번 제외 판정은 호우의 영향 크기를 추정한 결과가 아니라 **원본의 구조·날짜 부족**에 근거한다. [기상청 자료 49쪽 이후](https://www.kma.go.kr/down/e-learning/hands/hands_56.pdf)

## 2023~2025년 전체 구조 재점검

2022년 파일 안에서 행 너비가 달라지는 문제를 발견한 뒤 기존 사용 범위도 다시 검사했다. 2023년 1월~2025년 8월의 운행시간·운행횟수, 기존 13개월 승차, 2024년 4~8월 구간 승객의 **82개 ZIP·354개 CSV·194,697,370행**이 대상이다. 각 자료의 수집 기간은 서로 같지 않다.

형식 부적합은 아래 두 파일뿐이었다. 두 파일은 다년 예측 특징을 만들 때 이미 제외되어 있고, 이번 검사로 새롭게 시험값을 고치거나 다시 선택하지 않았다.

- 운행시간 `2024.11.04-11.10`: 헤더 61열, 데이터 31열, 필수 도착 순서 헤더 부재.
- 운행횟수 `2023.01.02-01.08`: 필수 헤더 손상, 데이터 첫 행 22열·나머지 29열.

나머지 파일의 구조가 맞는다는 사실이 0·공란의 의미, 실제 서비스 운영, 완전한 노선 수록, 시간 단위를 보증하지는 않는다. [전체 감사 명세](results/overnight/archive_audit/audit.json)와 [파일별 결과](results/overnight/archive_audit/members.csv)에 검사 범위와 실패를 남겼다.

## 자료 제공기관에 확인할 구체적인 질문

외부 연락은 하지 않았다. 추후 정의 확인이 가능하다면 다음 질문과 실제 파일명을 함께 전달하는 것이 유용하다.

1. OA-21217의 `운행시간_XX시`는 초/분 중 무엇이며, 두 정류장의 도착·출발 중 어느 시각 차이인가? 정차·신호 대기가 포함되는가? 시간대는 출발·도착 중 어디에 귀속하는가?
2. 운행시간의 숫자 0, 공란, 날짜·노선 행 부재는 각각 무운행·집계 불가·수집 누락 중 어떤 상태인가? 평균의 운행 횟수 분모와 이상치 제거 규칙은 무엇인가?
3. OA-21218의 `재차인원합`은 구간별 카드 기반 재차 인원인지, 운행별 합인지? 경기 광역버스의 미수록 범위와 카드 외 승객 처리 기준은 무엇인가?
4. OA-21221의 `환승_시간_평균` 단위, 하차·승차 시각 정의, 환승 인정 시간, 사용자 유형별 합계 범위와 누락·비식별 처리 기준은 무엇인가?
5. 2024년 5월 28·29일 여러 자료의 빈 파일, 2022년 운행시간의 손상, 역사적 노선 ID 변경을 설명하는 공개 수정 이력·코드북이 있는가?

현재 공식 카탈로그와 관련 연구만으로 위 정의를 모두 확정하지 못했다. 따라서 운행시간은 원 단위의 상대 지수로, 승객·운행·환승은 각 자료의 기록 범위 안에서 해석한다.

## 재현

사례 환경에서 `python overnight.py schema2022`, `python overnight.py archives-audit`를 실행한다. 이미 확보한 출처 명세·해시가 필요하며 감사 과정은 기존 원본·예측 모델을 수정하지 않는다. 큰 원본의 전체 행을 읽으므로 두 작업을 동시에 실행하지 않는다.
