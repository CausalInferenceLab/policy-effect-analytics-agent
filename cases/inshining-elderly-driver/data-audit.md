최신 실행 결과·보류 11행·재현 명령은 [수집·결합 보고서](collection-report.md)에 있습니다. 출처·원본 해시는 [taas-qc.json](taas-qc.json)과 [population-qc.json](population-qc.json), 결합 범위는 [panel-qc.json](panel-qc.json)에 기록했습니다.

## 2. TAAS에서 직접 확인한 경로

1. 위 상세통계 URL에서 **교통사고(경찰DB) → 노인 관련 → (노인운전자) 사고 → 시도 시군구별·월별 (노인운전자) 교통사고**를 선택합니다.
2. 표의 조회 범위는 **2005~2025년**으로 표시됐습니다.
3. 2014년 1월~2019년 12월을 한 번에 조회하자 **“조회기간은 5년이하로 조회가 가능합니다”**라는 안내가 나왔습니다.
4. **2014년 1월~2018년 12월**과 **2019년 1월~12월**을 분리해 조회했습니다. 각 표에서 해당 연도 열을 확인했습니다.
5. 조회 후 표의 **시군구 체크박스**를 선택해야 시군구 행이 나타납니다. 기간 조회 시 표 옵션이 초기화될 수 있으므로 새 조회 후 다시 확인합니다. 메뉴 제목에 시군구가 들어 있어도 기본 표는 시도 합계일 수 있습니다.
6. 2019년 표에서는 종로구·중구·해운대구 등 실제 시군구 행을 확인했습니다. 같은 이름의 구는 반드시 시도와 함께 식별합니다.
7. 주석은 노인운전자 사고를 **가해운전자(1당사자)의 연령이 65세 이상인 교통사고**로 정의합니다. “노인 교통사고”, “노인보행자 사고” 메뉴와 구분합니다.
8. 표 도구에 **엑셀(xlsx) 다운로드**가 있습니다. 최초 화면 점검에서는 버튼만 확인했습니다. 후속 수집은 같은 공개 통계의 XML 응답을 사용했으며, XLSX를 확보했다고 표시하지 않습니다.

2014~2018년 조회 화면은 로컬 수집 기록으로만 보관하며 제출물에는 원화면 JPG를 포함하지 않습니다. 원출처는 [TAAS 공식 분석 화면](https://taas.koroad.or.kr/OBIP25/analysis/TypicalAnalysis.jsp)입니다.

2019년 시군구 조회 원화면도 같은 이유로 제외했습니다. 조회조건·공개 응답 해시는 `taas-qc.json`의 역사적 수집 기록으로 확인합니다.

화면은 조회 경로와 정의의 근거입니다. 추출 파일이나 완전성 검사를 대체하지 않습니다. 표에는 페이지 이동도 있으므로 현재 보이는 페이지만 전체 자료로 취급하지 않습니다. 후속 수집에서는 두 구간 각각 2페이지를 확보하고 전체 페이지와 지역 합계를 검증했습니다. 이번 점검에서 표시된 사고 수치는 열람했지만 지역 간 정책 효과나 사전 추세를 추정하지 않았습니다.

## 3. 수집 기록과 재현 범위

원본은 Git 제외 경로인 `data/raw/`에 보관했습니다. QC JSON에 출처·조회기간·조건·수집시각·파일명·SHA256을 남겼습니다. 두 구간을 같은 설정으로 내려받고 원본은 덮어쓰지 않습니다. 결과 표의 자동 생성 합계 열·행과 데이터 행을 구분합니다.

공개 클라이언트의 조회 조건 변환과 일반 핸드셰이크를 재현해 익명 공개 XML을 수집했습니다. 임시 세션·서버 식별값은 저장하지 않았습니다. 로컬 재생성에는 네트워크가 필요 없습니다. 외부 재배포와 반복 자동수집의 이용 조건은 아직 확정하지 않았습니다. 공식 공개 파일/내보내기를 우선하며, 웹 경로가 있다는 이유로 API 제공이나 자동수집 허용을 가정하지 않습니다. 계정·키가 필요한 경로는 별도 기록하고 비공개 세션 값은 저장·공유하지 않습니다. 원본·가공 패널은 상위 프로젝트 정책에 따라 제출하지 않습니다.

## 4. 정책 기록의 필수 필드

| 필드 | 원칙 |
| --- | --- |
| 관할·정책 수준·적용 지역 | 시도 공통사업과 시군구 추가사업을 구분. 중복 적용을 새 도입으로 세지 않음 |
| 발표일·조례 시행일 | 제공 개시일과 따로 기록 |
| 제공 시작일·정밀도 | 일자 불명은 월/연 정밀도로 남김. 임의로 1일을 채우지 않음 |
| 신청 개시·반납 소급 기준 | 과거 반납자 지원 자격을 과거 처치로 오인하지 않음 |
| 지급 예정일·실제 지급일 | 계획과 이행을 구분. 자료가 없으면 결측 |
| 최소 연령·거주·증빙 | 해당 연도 조건을 보관. 현재 조건을 과거로 복사하지 않음 |
| 금액·지급수단·예산·추첨·이월 | 전원 즉시 지급 정책인지 구분 |
| 중단·변경·추가 혜택 | 지속적 이진 처치 가정이 맞는지 확인 |
| 원문 URL·발행일·확인일 | 검색 인덱스만 읽었는지도 명시 |
| 시점 불확실·미도입 확인 | 불명과 실제 미도입을 구분 |

지역별 현재 기록은 [policy-register.yaml](policy-register.yaml)입니다. 전국 표는 아직 아닙니다. 조례 목록은 개시일 후보를 찾는 도구이며 최종 처치 기록은 사업 공고로 보강합니다.

## 5. 결합 후 패널에 필요한 열

| 열 | 정의 |
| --- | --- |
| `region_id`, `province_id`, `year` | 경계를 통일한 시군구 코드, 군집용 시도, 연도. 코드는 문자열 |
| `crashes65` | 해당 연도·발생지역의 65세 이상 가해운전자 사고건수 |
| `population65_start` | 직전 연도 12월 말 65세 이상 주민등록인구 |
| `crashes65_per_10000_residents` | `10000 * crashes65 / population65_start` |
| `treated`, `first_treat` | 기간 내 도입 여부, 최초 제공 연도. 미도입 확인 시 `first_treat` 결측 |
| 정책 품질 기록 | 시점 정밀도·미도입 검증 여부·부분 노출·설계 변경. 불확실 지역은 결합 전 제외 사유 기록 |

반납 수는 시도·연도 보조 표로 따로 유지합니다. 인구 비례로 시군구에 나누거나 같은 시도 값을 각 구에 복제해 표본 수를 늘리지 않습니다.

## 6. 분석에 넘기기 전 통과할 검사

- 고정한 분석 경계에서 `(region_id, year)`가 유일하고 동일한 지역 목록을 추적할 수 있는가?
- 전국 합계·시도 합계·시군구·일반구/행정시가 섞이거나 상하위 지역이 이중 집계되지 않았는가?
- 사고 원본의 연도별 합계와 추출 후 합계가 일치하는가? 월 합계와 연간 합계를 중복 더하지 않았는가?
- 2014~2019년 각 연도와 각 포함 지역의 값이 모두 있는가? 비공개·`-`·공란은 문서 확인 없이 0으로 바꾸지 않았는가?
- 분모가 양수이고 동일한 주민등록 범위·연령·지역으로 집계됐는가? 2014년 분모에 필요한 2013년 12월도 확보했는가?
- 신설·통합·분구·명칭 변경과 경찰 관할 차이를 원자료 코드로 추적했는가? 불가능하면 공통 상위 경계로 합산할 수 있는지 검토하고, 분할 추정은 하지 않았는가?
- 도입 여부 불명 지역이 미처치에 섞이지 않았는가? 광역 지원을 받은 지역이 대조군에 들어가지 않았는가?
- 코호트마다 -3~-1 및 +1 관측과, 각 비교 시점의 미도입 대조군이 실제로 존재하는가?
- 시군구 수와 독립적인 정책·시도 군집 수를 별도로 세었는가?
- 계획 변경 사유와 이미 열람한 정보를 기록하고 결과 계산 전에 최종 계획을 커밋했는가?

하나라도 핵심 정의·비교군을 복구할 수 없으면 분석을 강행하지 않고 이유를 기록합니다. 시도 단위로의 전환이나 월별 설계·기간 확장은 별도 계획 변경으로 처리합니다.
