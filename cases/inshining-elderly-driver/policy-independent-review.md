# 정책 시점·후보 분류 독립 검토

검토일: 2026-10-27 · 점검 담당: `/root/policy_independent_review` · 실행 담당과 분리된 읽기 전용 검토. 점검 담당은 이 보고서 두 파일만 작성했다.

## Final scope reviewed

이번 승인은 **14개 정책 시점 근거·9개 공식 출처·6개 잠정 2019년 분류**, 검사기와 테스트, 프로젝트 `AGENTS.md`·실행/검토 프로토콜, 최신 집계와 관련 문구의 정합성에 한정한다. 기존 레지스터의 모든 금액·연령·예산·사망자 등 비시점 필드를 포괄 승인하지 않는다. 입력·검토 대상 SHA256과 재현 스크립트는 [기계 판독 보고서](policy-independent-review.json)에 있다.

## Findings

해당 단계의 미해결 차단 결함은 없다. 검토 중 발견·공유한 문제는 작성 담당이 수정한 뒤 재검증했다.

- 명시적인 `SEARCH INDEX EXCERPT` 스냅샷을 `direct`로 바꿔도 통과하던 사례는 이제 `retrieval_marker_mismatch`로 차단된다. 표지 없는 자료의 진위까지 자동 판별하는 것은 아니다.
- 알려진 2020년 개시일과 2019년 예고 불확실성이 공존하는 부안은 날짜를 지우거나 후보로 자동 승격하지 않고 `hold`를 유지한다. 날짜 근거·보류 사유·미해결 확인 사항이 필요하다.
- 초기 전북 `vtm` 경로의 오류·빈 본문은 근거로 인정하지 않았다. 실제 정상 답변을 제공하는 같은 `dataSid`의 공식 `governor` 경로로 교체한 뒤 독립 재조회했다.
- 전주·군산을 모두 ‘최초 시행 확정’으로 읽을 수 있던 주변 문서는 전주의 ‘2020년부터 시행’ 설명과 군산의 명시적 최초 시행 근거를 구분하도록 좁혀졌다.
- 서울의 반납 기간 3월 15일을 지원 신청 개시일로 확정했던 기록은, 공식 본문의 ‘지난 3월부터 … 사업을 시행’ 설명에 맞춰 **2019-03/month**로 좁혀졌다. 최신 인용·분류·레지스터·README·집계 해시를 확인하고 CLI를 다시 실행했다.

## Automated checks

```sh
.venv/bin/python cases/inshining-elderly-driver/audit_policy.py --output /tmp/policy-independent-checks.json
.venv/bin/python -m unittest discover -s cases/inshining-elderly-driver -p 'test_*.py' -v
```

실제 입력 CLI는 종료 코드 0, `errors=0, warnings=1, unknowns=2; analysis_approved=false`다. 전체 로컬 테스트 **53개가 통과**했다. 마지막 서울 인용·정밀도 수정 후 최신 입력 CLI를 재실행했으며, 검사 코드가 바뀌지 않아 53개 테스트와 아래 13개 합성 검사의 앞선 독립 실행 증거를 재사용했다. 실행 담당의 검사 결과 파일은 덮어쓰지 않았다.

별도의 임시 합성 자료로 **13개 CLI challenge**를 실행했다. 누락 근거, 해시 변조, 존재하지 않는 날짜, 조례만으로 제공 개시, 소급 자격만으로 제공 개시, 2019년 도입을 candidate로 표시, unknown을 candidate/0으로 표시, 승인 true, 명시 색인자료의 direct 위장을 모두 차단했다. 정상적인 known-date hold는 유지하고, 미해결 항목 또는 날짜 근거가 없는 hold는 차단했다. 스크립트 전체와 실제 종료 코드·오류 코드는 JSON 보고서에 보존했다.

독립 HTTP 재조회는 공식 URL **9/9 정상 본문**, 해당 **14/14 정확 인용**을 확인했다. 모든 스냅샷 헤더의 URL은 JSON과 일치하며 빈 오류 응답이나 색인 표지가 없다. 기존 QC에 기록된 **사고 XML 4개·인구 CSV 6개**, 기존 가공 파일 **4개의 해시가 일치**했다. 최신 집계의 파일 해시 19개와 정책 요약도 실제 파일·독립 실행에 일치했다. 관련 문서의 로컬 링크 16개가 존재한다.

전주·군산은 각각 2014~2019년 6행, 부산은 16개 코드·96행이 있다. 관측 존재와 해시 유지가 비교군 적격성·경계 일치의 증명은 아니다.

## Residual limitations

전주·군산의 2019년 발표·예고·예산·조례·다른 주체의 선행 지원 부재와 비교 가능성은 아직 확인해야 한다. 부산의 구군별 적용과 지원 기회 지속성·정확한 첫 제공·실제 지급일, 경계 이력, 연령 범위, 사전 추세, 소수 정책 군집의 추론과 교육제도 차등 노출도 남아 있다.

SHA256과 인용문 일치는 저장 텍스트의 일치를 뜻하며 문서 진위나 선행사업 부재를 증명하지 않는다. 이번 검토는 공식 본문을 별도로 직접 재조회했다. 과거 집계에 있는 offline replay나 상위 전체 테스트까지 이번에 새로 수행했다고 주장하지 않는다.

부산 5030과 면허반납 정책의 **고유 효과가 분리됐다고 승인하지 않는다**. 한계를 기록하거나 연도 효과·군집 표준오차를 쓰는 것만으로 부산 고유의 혼입이 제거되지 않는다. 정상 테스트 통과는 인과 식별 완료가 아니다.

## Approval scope

**정책 시점 근거 정리·잠정 후보 분류 및 검사/검토 절차 단계만 승인한다.** 모든 정책 `analysis_approved=false`, 비교군 적격성 승인 `false`, 최초 인과 분석·추정 승인 `false`를 유지한다. 전국 정책 패널 완성·최종 분석표본 확정·효과 추정·사전등록은 이번 승인 범위에 없다.
