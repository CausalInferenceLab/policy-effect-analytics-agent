### 측정일시 해석

에어코리아 공개용 1시간 자료는 **종료시각(Endtime)**을 쓴다. 원자료 `01시`는 `00:00~00:59:59`, `24시`는 같은 날 `23:00~23:59:59`의 관측값이다. `fetch.py`는 `HOUR_LABEL = "end"`로 설정하여 1시간을 빼고 관측 시작시각으로 정리한다.

근거: 환경부·국립환경과학원, [대기오염측정망 설치·운영지침(2016), 책자 142쪽·PDF 150쪽](https://www.keco.or.kr/download.do?uuid=201701170510459480#page=150). 지침의 예시는 `02:00~02:59:59 → 03시 자료`다.

운행제한 `06:00~21:00`은 원자료의 `07~21시` 행, 변환한 시작시각의 `06~20시`에 해당한다. 시간대 분석에 사용할 `hour`는 이 보정을 마친 `datetime`에서 만들어야 한다. 예를 들어 원자료 `07시` 행의 `hour`는 `6`, 원자료 `24시` 행의 `hour`는 `23`이다.

### 시간대별 분석과 반증 검사

시간대와 분석 방법은 `plan.yaml`에서 선언하고, `fetch.py`는 그 설정에 필요한 표를 만든다. 현재 연결된 설정은 다음과 같다. 실제 대기질 추세나 효과를 계산하기 전에 계획을 확정해 커밋한다.

| 파일 | 설정·구현 | 목적 |
|---|---|---|
| `fetch.py` | 보정된 `datetime`에서 0~23의 `hour`를 만들고 출력에 포함 | 각 행이 실제로 어느 시간대의 관측인지 표시 |
| `plan.yaml`의 `time` | `hour_col: hour`, `active_hours: [6, 21]` | 06:00~20:59의 자료로 주 분석 |
| `plan.yaml`의 `refutations` | `kind: placebo_window` | 21:00~다음 날 05:59의 자료로 같은 계산을 반복 |
| `plan.yaml`의 `abstention` | `placebo_window_significant`이면 `conditional` | 적용 외 시간대에서도 변화가 잡히면 해석을 낮춤 |

시행 시각(`treat_time`)은 실제 첫 운행제한 시각인 `2019-12-01 06:00`(`hour_idx=25542`)이다.

수집 단계에서는 적용 외 시간대를 버리지 않고 24시간을 모두 남긴다. `core.pipeline.split_hours()`가 한 표를 주 분석용과 반증 검사용으로 나눈다. 측정소·시각·처치 여부·결과변수의 열 이름도 계획과 표가 일치해야 한다.

반증 검사는 **정책 효과라는 해석이 의심되는 상황을 일부러 찾아보는 검사**다. 야간 자료에도 동일한 처치·대조 비교를 적용해, 녹색교통지역 안의 변화가 구역 밖보다 컸는지 확인한다. 서울 전체의 야간 대기질이 변했는지만 보는 검사는 아니다.

주간뿐 아니라 야간에도 처치·대조의 차이가 변하면, 운행제한 시간에만 나타나는 효과라는 설명을 재검토한다. 다른 정책·지역별 활동 변화가 원인일 수도 있고, 주간의 배출 변화가 밤까지 이어졌을 수도 있다. 따라서 야간의 유의한 결과는 점검 신호이며, 주간 효과가 거짓이라는 확정 판정은 아니다. 야간에서 유의하지 않아도 정책 효과가 증명되지는 않는다. 반증 검사의 논리와 전제는 [Lipsitch 등(2010)](https://dash.harvard.edu/entities/publication/73120379-21f6-6bd4-e053-0100007fdf3b)을 참고한다.

현재 공통 구현은 야간 추정의 p값을 `pretrend_alpha`(이 계획은 0.10)와 비교한다. 주간과 야간 효과의 차이를 직접 검정하는 DDD와는 구분한다.

### 주 단위 이벤트 스터디의 기준과 범위

현재 계획의 `method: event_study`는 시행일을 기준으로 주별 처치·대조 차이의 변화를 추정한다. 측정소·날짜시간 고정효과는 원래의 시간별 관측에 적용하며, 상대시점만 `event_bin: 168`로 주 단위로 묶는다. 이 선택은 [시간 단위 가이드](../../docs/strategy/plan-guide.md#시간-단위-자료-예-측정소--시간)에 맞춰 사전 계획으로 정했다.

| 설정 | 현재 값과 의미 |
|---|---|
| `event_bin: 168` | 1주 = 168시간. 계수와 그림의 상대시점은 주 단위 |
| `ref_period: -23` | 기준 주는 2019-06-23 06시~06-30 06시. 시범 운영 이전의 온전한 주 |
| `window: [-30, 12]` | 30주 이전은 왼쪽 끝, 12주 이후는 오른쪽 끝 계수에 묶음. 창 밖 자료도 사용 |
| `placebo_time.params.shift: 52` | 52주 전인 2018-12-02 06시를 가짜 시행 시각으로 사용 |
| `min_pre_periods: 105` | 최소 사전 기간 권고 기준을 약 2년에 해당하는 주 단위로 점검 |

예를 들어 시행 50주 전 관측은 `-30` 계수에, 시행 2주 후 관측은 `2` 계수에, 시행 60주 후 관측은 `12` 계수에 들어간다. 마지막 계수는 12주 이후의 긴 기간을 묶은 값이다. 12주까지만 분석하려면 자료의 사후 기간도 별도로 제한해야 한다.

시범 운영기인 2019년 7~11월을 제외하므로 주 분석의 직전 주(`-1`)에는 관측이 없다. 따라서 제외 기간에 걸리지 않는 `-23`주를 기준으로 고정하고, 실제 관측과 결측 여부는 자료 품질 점검에서 확인한다. 이 설정과 창의 구체적인 값은 이 케이스의 선택이며 멘토가 숫자까지 지정한 것은 아니다.

2019년 7~11월의 비어 있는 계수를 보간하거나 0으로 채우지 않는다. 시범 운영 이전 기준 주와 시행 사이의 추세를 직접 확인할 수 없으므로, 사전계수 자동 검정과 수동 추세 점검을 함께 사용하고 이 간격의 한계를 기록한다.

공통 리포트의 평균 추정치는 사후 주별 계수의 **단순평균**이다. 12주 이후를 모은 오른쪽 끝 계수도 하나로 센다. 따라서 이를 5년 표의 모든 시간에 같은 가중치를 준 평균이나 12주까지만의 효과로 해석하지 않는다.

2026-10-18 계획 정리에서는 공통 지원 #15와 멘토 피드백을 반영해 24시간 평균 DiD에서 시간대별 주 단위 이벤트 스터디로 설계를 변경했다. 기준 주·52주 전 가짜 시각·주 단위 최소 사전 기간을 함께 정했으며, 실제 대기질 추세와 정책 효과를 계산하기 전의 변경이다.

이 3곳의 처치 이후 변화는 별도로 보고하되, 변화만으로 정책에 의한 우회·확산 효과라고 단정하지 않는다. 한강대로·정릉로는 경계 최단거리가 2km 이상이어도 본분석에 편입하지 않는다.

**자료 길이로 제외: 시흥대로(111282)**

[서울시 2018년 12월 발표](https://mediahub.seoul.go.kr/archives/1202058)에서 신설을 확인했다. 2017년부터의 분석창을 덮지 못하므로 제외한다.

선정 기준은 분석기간의 자료 길이, 정책 영향·우회 가능성, 정책 전 도로·토지이용·교통 구성, 대규모 개발·측정소 이전 등 추세 차이의 위험이다. 명단은 결과를 보기 전에 고정하며, 적합성에 문제가 발견되면 해석을 보류하고 설계 변경 이유를 별도 커밋에 남긴다.

### 적은 처치 측정소와 추론

처치 측정소 2곳은 같은 정책구역에 속한다. 시간별 관측이 많아져도 정책을 받은 측정소 수는 2곳이고, 독립된 정책 사례가 2개인 것도 아니다. [B 트랙 안내](../../docs/tracks/analysis.md)는 처치 단위가 1~5곳인 경우 합성통제를 고려하도록 안내한다. 합성통제는 여러 대조 측정소를 조합해 정책 이전 처치 측정소와 비슷한 비교 대상을 만드는 방법이다. 현재 공통 모듈에서는 준비 중이므로, 무작위화 추론으로 1차 추정하고 이 설계의 한계를 기록한다.

무작위화 추론의 999회는 [`core/estimators/ri.py`](../../core/estimators/ri.py)가 수행하는 다음 계산이다.

1. 종로·청계천로를 실제 처치군으로 놓고 변화를 추정한다.
2. 대조 후보 9곳에서 2곳을 무작위로 골라 가짜 처치군으로 표시하고, 같은 날짜·방법으로 다시 계산한다. 실제 정책 시행 대상이 바뀌는 것은 아니다.
3. 2번의 선택과 계산을 999회 반복한다. 실제 추정치의 절댓값 이상인 가짜 추정치가 얼마나 자주 나오는지 비교한다.

가짜 대상에서도 비슷하거나 더 큰 변화가 흔하면 실제 대상의 변화가 특별하다는 근거가 약하다. 비교의 타당성은 측정소의 비교 가능성에 달려 있으므로, 자동 계산만으로 인과관계가 확정되지는 않는다.

본분석 후보 9곳에서 두 곳을 고르는 조합은 36종류이고, 핵심 후보 4곳만 쓰면 6종류다. 따라서 999회에는 같은 조합이 반복되며, 새로운 측정소나 독립적인 정책 사례가 999개 생기는 것이 아니다. 대조군은 p값을 낮추기 위해 늘리지 않고 앞의 선정 기준에 따라 고정한다.

실행자는 999번 명령을 실행할 필요가 없다. 분석 전에 결과변수의 결측이 없는지, 모든 측정소에 같은 관측시점이 있는지, 같은 시점에 도입되었는지와 대조 후보의 비교 가능성을 확인한다. 현재 계획의 공변량은 비어 있다. 조건을 확인하고 계획을 커밋한 뒤 `make flow`를 한 번 실행하면 공통 코드가 조건에 따라 무작위화 추론을 수행한다. 조건이 충족되지 않으면 이 케이스의 계획에 따라 해석을 보류한다.

완전 관측을 가정해도 현행 기간은 약 44만 행이다. 시간대 분리 후 주 분석도 약 28만 행이어서 999회 반복 계산에 시간이 걸릴 수 있다. 먼저 합성 자료로 수집기를 확인하고, 짧은 기간의 구동 확인은 본계획과 구분해 수행한다. 실제 결과를 보기 전에 기간 선택과 그 이유를 기록한다.

### 계절관리제·코로나 등 겹치는 변화의 점검

우선 공식 발표로 **언제, 어디에, 어떤 조치가 적용됐는지** 정리한다. 같은 서울에 속한다는 이유만으로 모든 측정소가 같은 영향을 받았다고 가정하지 않는다.

| 시점 | 확인한 내용과 출처 | 분석에서 확인할 점 |

이 표는 정책 적용 범위와 시점을 확인한 것이며, 각 측정소의 실제 영향 크기를 측정한 결과는 아니다.

기간을 바꾸어 확인하는 민감도 분석은 **같은 에어코리아 표**로 시작할 수 있다. 새로운 수치 자료가 있어야만 가능한 작업은 아니다. 정책 전 비교 기간(2017년 1월~2019년 6월)은 유지하고 정책 후 기간을 달리해 결과의 방향·크기·불확실성을 비교한다.

- **계획에 정한 비교**: 전체 기간, 정책 후를 2019-12-01~2020-01-31로 제한한 경우, 2019-12-01~2020-01-19로 제한한 경우, 2020년 관측을 제외한 경우. 수집기는 본분석 표를 만들며 이 민감도 분석을 자동 실행하지 않는다. 분석 단계에서 별도 실행하고 사용 기간을 기록한다.
- 2020-01-19 종료 창은 국내 첫 확진자 발생 이후를 제외하는 비교이며, 짧은 사후 기간의 한계를 함께 보고한다. 이 날짜만으로 모든 코로나 관련 행동 변화가 제거된다고 보장하지 않는다.
- 2020년만 제외해도 2021년의 코로나 영향을 제거한 것은 아니다. 단기 창 역시 계절관리제와 주차요금 변화를 제거해 주지 않는다.

기간별 결과가 다르면 원인을 추가로 살피고, 같아도 다른 정책의 영향이 없다고 확정하지 않는다. 서울 전체에 동일한 크기로 작용하는 충격은 날짜시간 고정효과로 반영되지만, 측정소별로 다른 영향은 남을 수 있다.

차이를 더 설명할 필요가 있으면 지역별 기상·정책 시행 강도·활동 자료 등을 추가 후보로 검토한다. 교통량은 운행제한이 대기질을 바꾸는 경로일 수 있으므로 자동으로 통제변수에 넣지 않는다. 추가 자료·변수·모형은 추정 전에 정한다. 같은 시기 도심에 겹친 정책을 현재 설계로 분리할 근거가 부족하면, 운행제한만의 효과라는 해석을 보류한다.

### 계획 커밋 후 수행할 점검

- 좌표로 경계 최단거리와 도심 접근·우회 가능성을 보고한다. 결과에 따라 대조군을 자동 교체하지 않는다.
- 측정소·항목별 관측 시작·종료일, 사전/사후 결측률과 이전·측정환경 변화 이력을 확인한다. 결측을 0으로 채우거나 보간하지 않고, 공통 품질검사의 결측률 20% 초과 등 실패 조건에 걸리면 추정을 중단한다.
- 사전추세는 시범 운영 전인 **2017년 1월~2019년 6월**로 점검한다. 2019년 7~11월은 처치·대조 모두에서 제외한다.
- 도시대기 측정소를 사용하는 보조 분석은 위치·관측기간을 별도로 확인해 추가 계획을 작성한다. 이번 본분석은 도로변대기 측정망으로 고정한다.
- 핵심 4곳 민감도 분석과 별도 3곳의 변화 분석은 계획으로 기록한 것이며, 현재 `fetch.py` 실행은 본분석 11곳의 표만 만든다.

### 자료 정리 실행

1. 위 시간대·주 단위 설정과 민감도 분석 기간이 담긴 `plan.yaml`을 검토한다. 대기질 추세와 정책 효과를 계산하기 전에 계획을 확정해 커밋하고 계획 PR을 제출한다.
2. 에어코리아 최종확정 측정자료를 내려받아 `data/raw/<연도>/<연도>년 <월>월.xlsx`에 넣는다. `1월`, `01월` 표기 모두 가능하다. 현재 `fetch.py`는 내려받은 파일을 읽는 정리 프로그램이며, 원자료 다운로드는 사용자가 수행한다. 본분석 대조군 9곳과 `HOUR_LABEL = "end"`가 설정돼 있다.
3. 프로젝트 공통 의존성과 이 케이스의 추가 의존성을 설치한 환경에서 실행한다.

```bash
python -m pip install -r cases/yesolee-green-traffic/requirements.txt
python cases/yesolee-green-traffic/fetch.py
```

`data/panel.csv`에는 측정소 코드·원래 측정일시·읽기 쉬운 날짜시간·정수 시간·실제 시간대(`hour`)·처치군 표시·NO₂·PM2.5가 저장된다. 시범 운영기(2019년 7~11월)는 양쪽 집단에서 제외하고, 빈칸·-999는 결측으로 둔다. 출처와 실행 설정은 `data/panel.source.json`에 기록한다. 원자료는 수정하지 않으며 데이터 파일은 커밋하지 않는다.

계획 검토와 자료 품질 점검을 마친 분석 단계에서는 프로젝트 의존성이 설치된 환경에서 `make flow CASE=cases/yesolee-green-traffic`로 추정을 실행한다. 결과 해석과 실제 점검에서 발견한 한계는 그때 `discussion.md`를 작성해 기록한다. 원자료·가공 표는 [기여 가이드](../../CONTRIBUTING.md#6-올리면-안-되는-것)에 따라 공유하지 않고, 원자료를 구하는 방법과 준비 코드를 공유한다.

실제 대기질 수치 대신 합성 자료로 수집기만 검사하려면 다음을 실행한다.

```bash
python cases/yesolee-green-traffic/test_fetch.py
```
